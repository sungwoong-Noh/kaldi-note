# kaldi note 브랜드 가이드라인

> 이 문서는 **AC를 갖지 않는다.** `docs/design/`의 다른 문서와 같이 「왜 이렇게 생겼는가」를
> 설명한다. 기계적으로 검증되는 값은 스펙과 테스트에 있다
> (`docs/specs/2026-09-07-visual-hierarchy.md`).
>
> **작성 방식:** 새로 지어내지 않았다. **이미 제품에 있는 것을 읽어서 성문화했다.** 목소리는
> 화면과 백엔드 진단 문구에서, 색과 타이포는 `globals.css`에서 뜬 것이다.

---

## ★ 토큰의 단일 진실 원천은 이 문서가 아니다

**색 값은 `frontend/src/app/globals.css`에 있다.** 이 문서는 그것을 **가리키기만 한다.**

```
frontend/src/app/globals.css        ← 값이 사는 곳
  ↑ 파싱해서 검증           src/test/contrast.test.ts · designTokens.test.ts
  ↑ 파싱해서 사용           scripts/make-icons.mjs
```

**이 문서에 hex를 옮겨 적으면 안 된다.** 옮겨 적는 순간 두 곳이 되고, 한쪽만 고쳐진다 —
이 저장소가 반복해서 겪은 실패다(`docs/JOURNAL.md` 2026-09-06「스펙과 README가 3주 넘게
어긋나 있었다」, 2026-09-07「계획 체크박스 38개가 비어 있었다」).

아래 표의 값은 **설명을 위한 사본이며 권위가 없다.** 어긋나면 `globals.css`가 옳다.

---

## 1. 이 제품이 무엇인가

**커피 레시피를 재현 가능한 형태로 기록하고 공유한다.**

브랜드의 중심 개념은 **재현 가능성**이다. 그래서 제품 구조 자체가 브랜드 주장이다.

| 구조 | 무엇을 주장하는가 |
|---|---|
| Recipe(설계도)와 BrewLog(기록)를 나눈다 | 「이렇게 내릴 것」과 「이렇게 내렸다」는 다른 것이다 |
| BrewLog가 레시피 값을 스냅샷으로 갖는다 | 과거는 조작되지 않는다 |
| 분쇄도 환산은 언제나 「추정치」다 | 모르는 것을 아는 척하지 않는다 |
| TDS 없이도 온전히 동작한다 | 장비가 없다고 배제하지 않는다 |

이 넷은 `CLAUDE.md`의 「뒤집으면 안 되는 설계 결정」이다. **브랜드를 이유로도 뒤집지 않는다.**

### 사용 환경이 디자인을 정한다

**부엌에서, 폰으로, 젖은 손으로, 느린 회선에서 쓴다.** 이 문장이 아래 결정 전부의 근거다.

- 웹폰트를 받지 않는다 — 0바이트·즉시 렌더
- 터치 타깃 최소 44×44px (`docs/conventions/frontend.md`)
- 숫자에 `tabular-nums` — 목록에서 값이 흔들리면 흘깃 볼 수 없다
- 오프라인에서 저장된 레시피가 열린다

## 2. 목소리

### 세 가지 규칙

**① 사실을 먼저 말하고, 그다음 무엇을 할지 말한다.**

```
추출이 부족합니다. 분쇄를 곱게 하거나 물 온도를 올리거나 추출 시간을 늘려보세요.
농도가 옅습니다. 물을 줄여 비율을 진하게 조정해보세요.
```

진단이 먼저, 처방이 뒤다. 처방은 **사용자가 실제로 돌릴 수 있는 손잡이**로 쓴다(분쇄·온도·시간).
「더 맛있게 내려보세요」처럼 손잡이가 없는 말은 쓰지 않는다.

**② 못 하는 것을 숨기지 않는다.**

```
TDS 측정값이 없어 추출 수율을 계산할 수 없습니다. 비율과 관능 평가로 판단하세요.
이 그라인더는 환산 정보가 없습니다
약 660 µm (추정치)
추출 수율 25.0%는 물리적으로 불가능합니다(최대 22.0%). 측정값을 다시 확인하세요.
```

**무엇이 없어서 못 하는지**를 정확히 말하고, **대신 무엇으로 판단할지**를 준다. 빈 화면으로
넘기지 않는다.

**③ 결과를 미리 말한다. 사과하지 않는다.**

```
내린 기록은 되살릴 수 없습니다.
일시적인 오류가 발생했습니다.
```

파괴적 행동은 결과를 먼저 알린다. 오류에는 변명이나 사과를 붙이지 않는다 — 「죄송합니다」는
사용자가 할 일을 알려주지 않는다.

### 문장 형태

| 규칙 | 예 |
|---|---|
| 평서형 `~습니다` | 「아직 기록이 없습니다」 |
| 버튼은 **행동**으로 | 「이 레시피로 내렸다」 · 「내 레시피로 가져오기」 · 「스텝 추가」 |
| 외래어보다 우리말 | 「포크」가 아니라 **「내 레시피로 가져오기」** |
| 느낌표를 쓰지 않는다 | 「복사했습니다」 (「복사했습니다!」 ✗) |
| 사용자를 부르지 않는다 | 「회원님」·「당신」을 쓰지 않는다 |

**버튼 라벨 「이 레시피로 내렸다」가 이 제품 목소리의 요약이다.** 과거형 평서문이고, 커피
용어(「내리다」)를 쓰며, 무엇을 기록하는지가 라벨 자체로 드러난다.

### 쓰지 않는 말

- 마케팅 형용사 — 「완벽한」·「최고의」·「손쉽게」
- 감탄과 응원 — 「멋져요!」·「잘하셨어요」
- 모호한 정도 표현 — 「적절히」·「빠르게」 (이건 인수 조건 규칙이기도 하다)
- 사과 — 「죄송합니다」·「불편을 드려」

## 3. 색

**값은 `globals.css`에 있다.** 여기서는 **각 색이 무엇을 뜻하는지**만 정한다.

| 역할 | 토큰 | 뜻 | 어디에 |
|---|---|---|---|
| 강조 | `--color-brand` | **행동할 수 있다** | 주 액션 버튼, 활성 탭, 아이콘 바탕 |
| 강조 위 글자 | `--color-on-accent` | — | brand·danger 위의 글자 |
| 조치 필요 | `--color-danger` | **사용자가 고쳐야 한다** | 오류, 삭제, 「12.5g 부족합니다」 |
| 보조 | `--color-muted` | **읽어도 되고 안 읽어도 된다** | 라벨, 힌트, 「(추정치)」 |
| 테두리 | `--color-line` | — | 카드·입력칸 경계 |
| 면 | `--color-surface` | — | 칩, 비활성 면 |
| 배경·본문 | `--background` · `--foreground` | — | 페이지와 글 |

### 지켜야 할 세 가지

**① 색은 액션에만 쓴다. 수치는 크기로 올린다.**

이 앱은 숫자가 주인공이지만 숫자를 브랜드색으로 칠하지 않는다. 목록에 카드가 쌓이면 갈색이
많아져 **정작 누를 것이 묻힌다.** 위계는 크기와 굵기가 만든다
(`docs/specs/2026-09-07-visual-hierarchy.md`).

**② 「조치 필요」와 「보조」를 색으로 구분한다.**

같은 안내라도 **사용자가 고칠 수 있으면 `danger`, 고칠 수 없으면 `muted`**다.

| 문구 | 색 | 왜 |
|---|---|---|
| 「12.5g 부족합니다」 | `danger` | 입력을 고치면 해결된다 |
| 「이 그라인더는 환산 정보가 없습니다」 | `muted` | 사용자가 할 수 있는 것이 없다 |

**③ 앰버를 쓰지 않는다.**

브랜드 브라운과 색상각 차이가 1~7°라 작은 글씨에서 구분되지 않는다. 「경고」가 필요하면
위 ②로 나눈다. 의미색은 **셋을 넘기지 않는다.**

### 대비

글자로 쓰이는 조합은 **전부 WCAG AA(4.5:1) 이상**이고, `contrast.test.ts`가 `globals.css`를
파싱해 매 실행마다 검사한다. 표면색(`line`·`surface`)은 글자가 아니라 대상이 아니다.

## 4. 타이포

**웹폰트를 받지 않는다.** 시스템 스택을 쓴다 — 부엌·느린 회선이 주 환경이라 0바이트가 실질
이득이 크다(`docs/specs/2026-09-05-polish.md`). 그래서 **기기마다 인상이 다르다**는 것을
받아들인다.

| 역할 | 크기 | 굵기 |
|---|---|---|
| 화면 제목 | 20px | semibold |
| **주요 수치** | 18px | semibold · tabular |
| 카드 제목 | 16px | medium |
| 본문 | 14px | normal |
| 라벨·보조 | 12px | normal · muted |

**다섯 단계 밖을 쓰지 않는다.** `designTokens.test.ts`가 막는다. 예외는 별 아이콘
(`text-[22px]`) 하나이고, 그건 글자가 아니라 도형이다.

**숫자는 `tabular-nums`다.** `body`에 걸려 있다. 목록에서 `20.0g → 300.0g`의 자릿수가
흔들리면 흘깃 봐서 비교할 수 없다.

## 5. 마크

소문자 `k` 하나. 둥근 사각형 바탕에 흰 글자다.

| 산출물 | 파일 |
|---|---|
| 파비콘 | `frontend/src/app/icon.svg` |
| 홈화면 아이콘 3장 | `frontend/public/icons/` — `make-icons.mjs`가 굽는다 |
| 상단바·상태바 | `manifest.json`의 `theme_color` |

**바탕색을 베껴 적지 않는다.** `make-icons.mjs`가 `globals.css`의 `--brand`를 읽는다. 토큰을
고치고 스크립트를 다시 돌리면 아이콘이 따라온다.

```bash
cd frontend && node scripts/make-icons.mjs
```

**라이트 값(`#6f4e37`)을 쓴다.** 다크 값은 밝아서 흰 글자가 2.20:1로 읽히지 않는다. 같은 이유로
`theme_color`도 라이트 값이다 — 매니페스트는 값을 하나만 갖는다.

**소문자를 지킨다.** 제품명도 `kaldi note`로 항상 소문자다. 「Kaldi Note」·「KALDI NOTE」로 쓰지
않는다.

## 6. 어긋난 것을 발견하면

**이 문서를 고치기 전에 `globals.css`와 스펙을 본다.** 이 문서는 파생물이다.

승인된 AC가 걸리면 **그 AC를 고치고 이유를 그 자리에 남긴다.** 2026-09-08에 `AC-PWA-04`가
그랬다 — 원래 「`theme_color`와 `background_color`가 **모두** `#ffffff`다」였는데, 그때는
브랜드색이 없어 흰색 말고 고를 것이 없었을 뿐이다.

## 열어둔 것

- **로고다운 로고.** 지금은 글자 `k`뿐이다. 워드마크나 심볼이 필요해지면 그때 만든다.
- **브랜드색의 농도 변형.** `--color-brand` 하나뿐이라 hover·pressed를 따로 두지 않는다.
- **간격 체계.** 이번 정비의 비목표였다. 「위계가 없다」는 인상에는 간격이 색보다 크게
  작용하므로, 다음에 볼 것은 아마 이것이다.
- **SCA 구간에 색을 줄지.** 의미색이 넷이 되고 「좋다/나쁘다」를 색으로 단언하게 된다.
