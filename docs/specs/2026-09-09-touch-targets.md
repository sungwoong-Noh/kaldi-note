# 터치 타깃 44×44px 스펙

> 2026-09-09 `/interview`로 확정. 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md).
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**

## 무엇을

**누를 수 있는 것을 전부 44×44px 이상으로 만들고, 그것을 검사한다.**

`docs/conventions/frontend.md:179`가 **「터치 타깃은 최소 44×44px. 부엌에서 젖은 손으로 쓴다」**
라고 규약으로 정해놓았으나 **아무도 검사하지 않는다.** 실측하니 11개 화면의 상호작용 요소
**178개 중 138개가 미달**이고, 명시적 크기 지정은 **0곳**이다.

**보이는 박스를 키운다**(`min-h-11`·`min-w-11`). 히트 영역만 넓히는 방식은 쓰지 않는다 —
★ 별점이 지금 30px 간격이라 44px 영역이 **14px씩 겹쳐** 어느 별을 눌렀는지 모호해진다.

**검사는 e2e 렌더 스윕 하나다.** 화면을 쓸어 모든 상호작용 요소를 모아 재므로, **목록에 없는 새
버튼이 나중에 추가돼도 자동으로 걸린다.**

**백엔드를 건드리지 않는다.** API·스키마·HTTP 응답 변경이 0건이므로 **이 스펙에는 에러 인수 조건이
없다.**

### 범위 밖 (Non-goals)

- **데스크톱·태블릿 뷰포트.** 360×800에서만 잰다. 이 저장소에 `md:` 이상 레이아웃을 검사하는
  테스트가 **한 건도 없고**, 「부엌에서 폰으로 쓴다」가 전제다.
- **간격·모서리·그림자 체계.** 지금 간격 12단계·모서리 3종·그림자 0곳이다. 이 스펙은 **최소
  크기만** 잠근다. 별도 스펙으로 남긴다.
- **`visual-hierarchy`의 색 8개·글자 크기 5단계.** 깨지 않는다. 이 스펙이 새로 쓰는 클래스는
  `min-h-11`·`min-w-11`뿐이며 둘 다 색도 글자 크기도 아니다.
- **백엔드 변경.** 0건.
- **키보드 포커스 링·대비 등 다른 접근성 항목.** 이번은 **크기 하나**다.

## 왜

**젖은 손으로 13×13px을 누른다.** 「내 레시피만」은 브라우저 기본 체크박스라 **13×13px**이다.
입력칸 69개가 **30px**, `select` 28개가 **29px**, 별점 버튼이 **30×22px**다.

**규약이 있는데 검사가 없으면 규약이 아니다.** `frontend.md`가 44×44px을 못박은 것은 2026-08이고,
그 뒤로 만들어진 화면 어디에도 크기 지정이 없다. `visual-hierarchy`와 `screen-consistency`가
**연속 두 번 「별도 스펙으로 분리한다」며 미뤘다.**

## 용어

| 용어 | 정의 |
|---|---|
| **상호작용 요소** | `button` · `a` · `input` · `select` · `textarea` |
| **예외** | `<p>` 또는 `<h1>`~`<h6>`의 **자손**인 `<a>`. 글줄 안에 놓인 링크다 |
| **통과** | `width ≥ 44` **그리고** `height ≥ 44` (CSS px, 뷰포트 360×800) |
| **스윕** | 한 화면의 상호작용 요소를 셀렉터로 **전부 모아** 한 번에 재는 것 |

## 대상과 예외

### 예외는 정확히 둘이고, 규칙으로 잡힌다

| 요소 | 크기 | 어디 | 왜 예외인가 |
|---|---|---|---|
| `James Hoffmann` | 110×17 | `RecipeDetail` — `<p>` 안의 출처 링크 | 글줄에 녹아 있다. 높이를 강제하면 줄간격이 무너진다 |
| 레시피 제목 | 283×23 | `BrewDetail` — `<h1>` 안의 링크 | 제목 줄이 부풀어 별점과 세로 정렬이 어긋난다 |

**규칙: `<p>` 또는 `<h1>`~`<h6>`의 자손인 `<a>`.** 지금 이 규칙이 **정확히 위 둘만** 잡는다는 것을
확인했다. 버튼처럼 생긴 링크 넷(`전체 보기`·`레시피`·`새 레시피`·`편집`)은 전부 `<h1>`의
**형제**이거나 `<div>` 안이라 자손이 아니다.

### 실측 현황 (2026-09-09, 360×800)

| | 값 |
|---|---|
| 11개 화면(`e2e/screens.ts`)의 인스턴스 | **178개** |
| 통과 | **40개** |
| 미달 | **138개** — 높이만 105 · 높이와 너비 둘 다 33 |
| 다이얼로그 4개 | **15개.** 스윕이 열지 않아 **아직 재지 않았다**. `py-1`·`py-1.5`+`text-sm`이라 계산상 28~32px |

**통과 40개의 정체:** `BottomNav` 탭 28개(90×44, 7화면×4) · 목록 카드 링크 6 · `textarea` 4 ·
전체폭 버튼 2. **의도해서 44px인 곳은 없다** — `BottomNav`의 `py-3`이 우연히 맞은 것이다.

**미달 높이 분포:** `input` 30px 69개 · `select` 29px 28개 · ★ 22px 10개 ·
「여기 아래에 추가」 20px 7개 · 버튼 32~42px 18개 · 체크박스 13px 1개.

## 어떻게 44px를 만드는가

**보이는 박스를 키운다.** `min-h-11`·`min-w-11`은 Tailwind v4 기본 스케일에서 `2.75rem`이고
이 저장소는 `--spacing`도 루트 폰트 크기도 재정의하지 않으므로 **44px**이 된다.

> **인수 조건은 클래스가 아니라 렌더된 px에 건다.** `min-h-11`이 44px가 아닌 것으로 드러나면
> 테스트가 잡는다. 클래스는 구현 수단일 뿐이다.

**가장 빡빡한 두 곳을 미리 계산했다.**

| 행 | 확장 후 폭 | 여유 |
|---|---|---|
| ★ 별점 (`RatingInput`) | 라벨 80 + 5×44 + gap 20 = **320px** | 328px 중 **8px** |
| 스텝 `↑ ↓ 삭제` (`RecipeStepEditor`) | 3×44 + gap 8 = **140px** + `select` | 넉넉 |

**8px 여유는 얇다.** 그래서 `AC-TOUCH-12`(가로 스크롤 0)가 이 스펙에서 가장 값진 조건이다.

## 어떻게 동작 — 인수 조건

### 정상 동작

#### AC-TOUCH-01 · 11개 화면의 상호작용 요소가 전부 44×44px 이상이다

- **Given** 360×800 뷰포트에서 `e2e/screens.ts`의 `SCREENS` 11개 경로를 차례로 연다
- **When** 각 화면에서 `button, a, input, select, textarea`를 전부 모아, **예외**(`<p>` 또는
  `<h1>`~`<h6>`의 자손인 `<a>`)를 뺀 나머지의 `getBoundingClientRect()`를 읽는다
- **Then** 남은 요소 전부가 `width ≥ 44`이고 `height ≥ 44`다. 미달 요소 목록이 **빈 배열**이다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-02 · 다이얼로그 4개 안의 요소도 전부 44×44px 이상이다

> **`/recipes/3`이다.** `/recipes/12`는 `hoffmann`인데 **`ownerUserId`가 없어**(주인 없는
> `CURATED`) 삭제 버튼이 뜨지 않는다 — 그 화면에는 「내 레시피로 가져오기」만 있다.
> `/recipes/3`은 `kasuyaRecipe`(`ownerUserId: 11`)이고 `me.id`가 11이라 소유자로 열린다.

- **Given** 다이얼로그를 여는 네 경로 —
  `/brews/new?recipeId=12`에서 `+ 원두 등록`(`BeanBatchDialog`, 7개),
  `/brews/new?recipeId=12`에서 `+ 그라인더 등록`(`UserGrinderDialog`, 4개),
  `/recipes/3`에서 `삭제`(`DeleteRecipeDialog`, 2개),
  `/brews/2`에서 `삭제`(`DeleteBrewLogDialog`, 2개)
- **When** 다이얼로그가 열린 뒤 `AC-TOUCH-01`과 같은 스윕을 돌린다
- **Then** 미달 요소 목록이 **빈 배열**이다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-03 · 예외로 빠지는 `<a>`가 정확히 2개다

- **Given** `/recipes/12`와 `/brews/2`
- **When** 각 화면에서 `<p>` 또는 `<h1>`~`<h6>`의 자손인 `<a>`를 센다
- **Then** `/recipes/12`에 1개(`James Hoffmann`), `/brews/2`에 1개(레시피 제목)다.
  나머지 9개 화면에는 **0개**다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-04 · ★ 별점 버튼 5개가 각각 44×44px이다

- **Given** `/brews/new?recipeId=12` — 지금 각 버튼이 30×22px이다
- **When** `aria-label`이 `별점 1`~`별점 5`인 버튼 5개를 잰다
- **Then** 다섯 개 모두 `width ≥ 44`이고 `height ≥ 44`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-05 · 스텝 행의 `↑`·`↓`·`삭제`가 각각 44×44px이다

- **Given** `/recipes/12/edit` — 지금 `↑`·`↓`가 29×30px, `삭제`가 42×30px이다
- **When** `aria-label`이 `스텝 2 위로`·`스텝 2 아래로`·`스텝 2 삭제`인 버튼을 잰다
- **Then** 셋 다 `width ≥ 44`이고 `height ≥ 44`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-06 · 「내 레시피만」 체크박스가 44×44px이다

- **Given** `/recipes` — 지금 브라우저 기본 체크박스라 **13×13px**이다
- **When** `getByRole("checkbox", { name: "내 레시피만" })`을 잰다
- **Then** `width ≥ 44`이고 `height ≥ 44`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-08 · 「원두량」 입력칸의 높이가 44px다

- **Given** `/brews/new?recipeId=12` — 지금 128×30px이다
- **When** `getByLabelText("원두량")`의 높이를 잰다
- **Then** `height`가 `44px`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-09 · 「공개 범위」 select의 높이가 44px다

- **Given** `/brews/2/edit` — 지금 99×29px이다. **`/brews/new`에는 이 select가 없다** —
  공개 범위는 `BrewLogEditor`(편집)와 `RecipeForm`에만 있고 작성 폼에는 없다
- **When** `getByLabelText("공개 범위")`의 높이를 잰다
- **Then** `height`가 `44px`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-10 · `BottomNav` 탭 4개가 90×44px 그대로다

- **Given** `/recipes` — 지금 각 탭이 90×44px로 **이미 통과**한다
- **When** `홈`·`레시피`·`기록`·`더보기` 링크를 잰다
- **Then** 넷 다 `width`가 `90px`, `height`가 `44px`다. **이 스펙이 그것을 바꾸지 않는다**
- **검증** e2e `e2e/touch-targets.spec.ts`

### 경계값

#### AC-TOUCH-07 · `disabled`인 `↑`·`↓`도 44×44px이다

- **Given** `/recipes/12/edit` — 첫 스텝의 `↑`와 마지막 스텝의 `↓`는 `disabled`다
- **When** `aria-label`이 `스텝 1 위로`인 버튼과 `스텝 7 아래로`인 버튼을 잰다
- **Then** 둘 다 `disabled` 상태이면서 `width ≥ 44`이고 `height ≥ 44`다
- **검증** e2e `e2e/touch-targets.spec.ts`

#### AC-TOUCH-11 · 판정 함수가 44.0을 통과로, 43.9를 미달로 준다

- **Given** 판정 함수 `meetsTouchTarget({ width, height })`
- **When** `{44, 44}` · `{44, 43.9}` · `{43.9, 44}` · `{43.99, 43.99}` · `{100, 44}`를 넣는다
- **Then** 차례로 `true` · `false` · `false` · `false` · `true`다. **허용 오차는 0이고 반올림하지
  않는다** — `43.99`는 미달이다
- **검증** 단위 테스트 `src/test/touchTarget.test.ts`

#### AC-TOUCH-12 · 11개 화면 어디에서도 가로 스크롤이 생기지 않는다

- **Given** 360×800 뷰포트에서 `SCREENS` 11개를 차례로 연다
- **When** 각 화면에서 `document.documentElement.scrollWidth`를 읽는다
- **Then** 전부 `360` 이하다
- **검증** e2e `e2e/touch-targets.spec.ts`

> **이 조건이 이 스펙에서 가장 값지다.** ★ 별점 행이 확장 후 `80 + 5×44 + gap 20 = 320px`로
> 328px 중 **8px만 남긴다.** 어디선가 넘치면 여기가 잡는다.

### 에러

**없다.** 백엔드 변경이 0건이고 새 HTTP 응답 경로가 없다.
