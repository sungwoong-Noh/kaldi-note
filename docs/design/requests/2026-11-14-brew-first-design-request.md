# Claude Design 요청문 — 「기록 먼저」 화면 재구성

```
kaldi note의 핵심 흐름을 다시 설계합니다. 이미 확정된 디자인 시스템(Clean Ledger)의 색·글꼴·토큰은 그대로 쓰고,
화면 구조·흐름·움직임을 새로 잡아 주세요.

[배경 — 왜 다시 그리나]
kaldi note는 핸드드립 커피를 내리고 기록하는 앱(웹 + PWA)입니다. 지금 두 사람이 쓰는데, 쓰다가 손을 놓았습니다.
이유: 커피 한 잔을 기록하려면 레시피를 먼저 쓰고, 원두를 등록하고, 그라인더를 등록해야 했습니다. 「서류 작성」이었습니다.

그래서 흐름을 뒤집습니다.
- 예전: "어떤 레시피를 만들어서 내릴까?" → 레시피 작성 → 기록
- 지금: "오늘은 이렇게 내려 보자" → 바로 기록 → "괜찮네" → 레시피로 저장 → 다음에 그 레시피로 다시 내려 비교
레시피는 입구가 아니라 「괜찮았던 기록을 저장한 것」이고, 다음 잔의 출발점입니다.

[목표 — 이걸로 판단합니다]
- 지난번과 같게 내렸으면 기록이 탭 3번으로 끝난다. 바꿔도 30초 안.
- 처음 보는 사람이 홈에서 무엇을 할지 바로 안다.
- "웹페이지"가 아니라 "잘 만든 서비스"처럼 느껴진다.

[첨부를 이 순서로 읽어 주세요]
1. docs/README.md — 토큰·컴포넌트 사전(색·글꼴·간격은 여기만 씁니다)
2. docs/DECISIONS.md — 확정 결정
3. system/Design System.dc.html, system/Navigation.dc.html
4. 지금 화면(참고, 바꿀 대상): screens/01 홈, 02 레시피·내 잔, 03 레시피 작성, 08 잔 상세

────────────────────────────────
[화면 원칙 — 토스에서 배운 구조, kaldi의 모습]
구조·흐름·움직임은 토스처럼, 색·글꼴·분위기는 Clean Ledger로 갑니다.
1. 한 화면에 한 가지. 화면(또는 시트 한 단계)마다 질문 하나, 주 버튼 하나.
2. 숫자가 주인공. 원두량·물량·비율은 화면에서 가장 크게(IBM Plex Mono). 입력하면 비율이 즉시 바뀐다.
3. 입력이 편하다. 숫자는 숫자 키패드, 단위는 옆에 고정, 지난번 값이 미리 채워져 있다. 앞자리 0("040초") 같은 표기 없음.
4. 아래쪽 큰 버튼 하나. 시트·화면의 주 행동은 하단 전폭 버튼(모바일은 키보드 바로 위).
5. 완료 화면이 있다. 저장하면 "기록했어요"와 요약, 다음 행동을 보여 준다.
6. 홈은 카드 묶음. 카드 하나에 정보 하나, 행동 하나.
7. 기다림이 안 느껴진다. 로딩은 뼈대(skeleton) 화면, 버튼은 누르는 즉시 반응.

[말투]
- 질문·버튼·완료는 대화체: "지난번과 같은가요?", "기록했어요", "레시피로 저장할까요?"
- 기록·통계 문장은 지금처럼 관찰형, 판단하지 않음: "이번 달 9번 중 7번이 92°C였습니다"

[움직임 — 각 화면 옆에 주석으로 적어 주세요]
- 시트·패널: 아래(웹은 오른쪽)에서 밀려 나옴, 200~250ms ease-out. 닫을 때 반대로.
- 세그먼트·탭 바: 선택 표시가 미끄러지듯 이동.
- 버튼: 누르면 살짝 눌림(scale 약 0.98).
- 숫자: 비율·통계 숫자가 바뀔 때 짧게 전환.
- 완료: 체크가 그려지는 짧은 애니메이션.
- 기기에서 "동작 줄이기"를 켰으면 모두 끈다.

[지키는 것]
- README의 토큰만. 새 색·그림자·그라디언트 없음. 아이콘 없이 텍스트 라벨(완료 체크 1개만 예외 제안 가능).
- 아래 [데이터]에 없는 정보는 그리지 않습니다. 꼭 필요하면 그리고 「API 없음」 라벨 + 끝의 질문 목록에.

[캔버스]
모바일 390×844와 웹 1440×900 둘 다. 라이트 기본, 모바일 다크 2장(홈·빠른 기록).
웹은 모바일을 늘리지 말고 웹답게: 본문 최대 폭을 정하고, 빠른 기록은 오른쪽 패널.

────────────────────────────────
[데이터 — 실제 필드]
기록(BrewLog): brewedAt(시각), actualDoseG(원두량 g), actualWaterG(물량 g), brewRatio(자동 계산, 1:15.6),
  actualWaterTempC(°C), actualTotalTimeSeconds(m:ss), actualDrawdownSeconds, 그라인더(userGrinder) + actualGrindSettingValue(클릭·눈금),
  actualGrindMicronEstimated(추정 µm — 항상 「약 · 추정치」), beverageWeightG, tdsPercent, extractionYieldPercent(수율 — TDS 없으면 비움),
  rating(별점 0.5~5.0), acidity·sweetness·body·bitterness·aftertaste(각 1~5), overallNote(메모 1000자),
  visibility(PRIVATE 나만 | FRIENDS 맞팔로우 | PUBLIC 전체), recipeId(선택 — 레시피 없이도 기록), daysOffRoast(로스팅 후 일수),
  degassingStatus(TOO_FRESH 너무 신선 | IDEAL 적정 | PAST_PEAK 지남)
원두(카탈로그, 크롤링으로 채워짐): 상품명, 로스터 이름, roastLevel(LIGHT | MEDIUM_LIGHT | MEDIUM | MEDIUM_DARK | DARK, 없을 수 있음),
  decaf, 산지(국가·지역·농장, 블렌드면 여러 개 또는 없음). 내 원두 봉투: roastedAt(로스팅 날짜), remainingG(남은 양).
레시피: 이름, 원두량·물량·온도(+ 총 시간), 장비·분쇄도·스텝은 선택, 원본 작성자(담아온 경우).

[이번에 바뀌는 규칙 — 그렇게 그려 주세요]
- 기록의 필수값은 원두량·물량 둘뿐. 시각은 자동. 원두·별점·메모는 선택, 나머지는 「자세히」.
- 원두는 최근 고른 것 / 카탈로그 검색 / 이름 직접 입력 중 하나로 한 번에 고른다(봉투 등록 단계 없음).
- 지난번 기록의 원두·원두량·물량·그라인더·분쇄도·온도가 새 기록에 미리 채워진다.

────────────────────────────────
[그려 주세요]

1) 오늘(홈) — 지금 01 홈(달력)을 대체
   - 상단: 날짜 + 짧은 인사 정도. 로고 바 대신 화면 제목 문법(eyebrow + 큰 제목)
   - 「기록하기」 — 화면에서 가장 큰 행동
   - 「지난번과 같게」 카드 — 마지막 기록 요약(원두·원두량→물량·그라인더 분쇄도) + 「이대로 기록」
   - 최근 기록 3~5개 — 원장 행: 날짜 · 원두(또는 레시피) · 별점이 한눈에. 눈에 띄는 정보 하나 + 흐린 보조 한 줄
   - 이번 주 몇 잔(작은 통계 하나)
   - 달력은 홈에서 뺀다(「기록」 탭으로). 팔로우 레일도 뺀다(나중 친구 피드에서).
   상태: 첫 사용자(기록 0) — 「첫 잔을 기록해 보세요」와 기록하기 하나만 / 기록 1개 / 많음 / 로딩 뼈대

2) 빠른 기록 — 어느 화면에서든 열리는 바텀시트(웹은 오른쪽 패널), 3단계
   ① "지난번과 같은가요?" — 원두·원두량→물량(크게)·비율·그라인더. [바꿀래요] [네, 같아요]
      「바꿀래요」 → 같은 시트에서 원두량·물량 숫자 칸 + 원두 선택이 편집 상태로
   ② 맛 — 별점 + 메모 한 줄. 「건너뛰기」 가능. ▸자세히(온도·시간·분쇄도·장비·맛 5축·TDS·공개 범위·레시피 연결)
   ③ 완료 — "기록했어요 · 이번 주 4번째 잔" + [레시피로 저장] [확인]
   상태: 첫 기록(지난번 없음 → ①이 바로 입력 상태) / 원두 고르기(최근·검색·직접 입력·검색 결과 없음) /
         필수값 비었음 / 저장 중 / 저장 실패(입력 유지) / 레시피에서 시작(값이 레시피로 채워짐)

3) 기록 상세 — 지금 08 B2를 이 흐름에 맞게
   - 맨 위 요약(대표 수치 하나), 아래 기록 내용
   - 행동: 「레시피로 저장」(레시피 없이 만든 기록일 때) · 「다시 내리기」(값을 채운 빠른 기록) · 수정
   - 레시피가 연결된 기록이면 지금처럼 레시피와 비교(차이를 문장으로)

4) 레시피로 저장 — 시트 한 장
   - 기록 값으로 채워진 4칸: 이름(필수) · 원두량 · 물량 · 온도. 「자세히」에 총 시간·장비·분쇄도·스텝
   - 완료: "레시피로 저장했어요" + [레시피 보기] [확인]

5) 레시피 작성(새로 만들 때) — 지금 03을 대체하는 간단판
   - 기본 4칸 + 「자세히」(공개 범위·HOT/ICE·추천 배전도·장비·분쇄도·스텝)
   - 레시피 상세의 주 행동은 「이걸로 내리기」 → 값이 채워진 빠른 기록

6) 「기록」 탭 — 지금 「내 잔」 목록을 이 이름으로
   - 상단에 「기록하기」, 목록/달력 전환. 달력은 웹에서 작게(본문 폭 안에서 적당히, 화면을 다 차지하지 않게)
   - 목록은 날짜로 묶은 머리글 + 원장 행(눈에 띄는 정보 하나)

7) 탭 바: 오늘 · 기록 · 레시피 · 더보기 (가운데 + 버튼은 넣지 않음)

[마지막에]
- 각 화면의 움직임 주석, 1280/1024/760 구간별로 바뀌는 점 표
- 제가 정해야 할 것을 질문 목록으로(각각 추천값과 근거)
```
