## 1. 기획 요약

### 사용자 쪽 — 「원두 상세」 1장 (+ 원두 고르기 보강)
목적: 내가 쓰는 원두가 어떤 원두인지, 그리고 **이 원두로 내가 어떻게 내렸는지**를 본다. 다음 잔으로 이어지게 한다.
둘러보기 목록은 만들지 않는다(B2). 들어오는 곳:
- 빠른 기록 「원두 고르기」 결과 행의 「정보」
- 기록 상세의 원두 행
- 오늘 홈 「지난번과 같게」 카드의 원두 이름

```
┌ 원두 상세 ─────────────────────┐
│ 산책 로스터스                    │  로스터
│ 에티오피아 구지 함벨라             │  이름(큰 제목)
│ 싱글 · ● 약배전 · 디카페인 아님     │  요약 칩
│ 「자두, 홍차, 꿀」                │  컵노트(사이트 원문 한 줄)
│ ─────────────────────────────  │
│ 산지  에티오피아 · 구지 · 함벨라    │  원장 행(블렌드면 비율별 여러 줄)
│ 고도  1,900–2,100 m             │
│ 품종  에어룸   가공  워시드        │
│ ─────────────────────────────  │
│ 이 원두로 내린 기록  5잔 · ★4.1   │  내 기록 요약
│ 자주 쓴 비율 1:15.6 · 16g→250g   │
│  11.13  16g→250g  ★4.0          │  최근 3개
│ [ 이 원두로 기록하기 ]  ← 주 버튼   │
│   구매처에서 보기 ↗               │  보조(외부 링크)
└─────────────────────────────────┘
```

### 관리자 쪽 — 「원두」 메뉴 (관리자 콘솔, 표 + 오른쪽 패널)
목적: 크롤러가 넣은 원두의 **빠진 정보를 채우고, 확인하고, 잘못 수집된 것을 숨긴다.**
- 목록: 검색 + 필터 + 표 + 일괄 「확인 처리」·「숨기기」
- 오른쪽 패널: 상세·편집
- 수집 실행 상세의 「매핑 못 한 원문」 → 해당 원두 편집으로 바로 이동(해당 칸 강조)

## 2. 확정 결정 (2026-11-15)

| # | 결정 | 값 |
|---|---|---|
| B1 | 사용자에게 보이는 원두 | 숨김 아닌 카탈로그 원두 전부(확인 안 된 것도 보임 — 「확인 필요」는 관리자에게만) |
| B2 | 원두 둘러보기 목록 | 만들지 않음 |
| B3 | 컵노트 | 사이트 원문 한 줄 + 구매처 링크까지 |
| B4 | 삭제 vs 숨김 | 숨김만. 재수집해도 숨김 유지. 숨긴 원두를 쓴 기록은 그대로 보임 |
| B5 | 관리자 시안 | Admin 캔버스의 장비 화면 문법(표 + 오른쪽 패널)을 따름 |
| B6 | 사진 | 없음 |
| B7 | 관리자가 고친 값 vs 크롤러 재수집 | **관리자가 수정한 원두는 크롤러가 덮어쓰지 않음**(이름·구매 링크만 갱신). 패널에 「수동 수정됨」 표시 |
| B8 | 사용자가 직접 입력한 원두(P1) | 만든 사람에게만 보임. 관리자 목록에는 출처 「사용자」로 보이고, 「카탈로그로 올리기」 가능 |
| B9 | 관리자 표의 「기록 수」 | 표시(이 원두로 남긴 기록 수) — 숨기기·병합 판단에 필요 |
| B10 | 마스터에 없는 가공·품종 | 이번엔 선택지에서 고르기만. 마스터 추가는 별도(품종 추가 API는 있음, 가공은 없음) |

## 3. 데이터 — 실제 필드

원두(bean_products): name · 로스터(roasters: name, country, website) · beanMix(SINGLE_ORIGIN 싱글 | BLEND 블렌드) ·
roastLevel(LIGHT 약 | MEDIUM_LIGHT 중약 | MEDIUM 중 | MEDIUM_DARK 중강 | DARK 강, 없을 수 있음) · roastLevelAgtron(숫자, 없을 수 있음) ·
roastLevelCustom(원문, 예 "Light #92") · decaf · productUrl(구매처) · description(컵노트 원문) · verified(확인됨) ·
createdByUserId(null이면 크롤러 소유) · createdAt · updatedAt
산지(bean_origins, 원두당 0~N): country · region · farm · altitudeMinM · altitudeMaxM · variety(품종 마스터) · process(가공 마스터) · ratioPercent(블렌드 비율, 합 100)
가공 마스터 예: 워시드 · 내추럴 · 화이트/옐로우/레드/블랙 허니 · 무산소 내추럴/워시드 · 카보닉 마세라시옹 · 락틱 · 써멀 쇼크 · 웻 헐드 …
새로 생기는 값(API 없음 — 이번에 만든다): hidden(숨김), 수동 수정 여부, 기록 수, 내 기록 요약(잔 수·평균 별점·자주 쓴 비율·최근 3개)

## 4. Claude Design 요청문 — 사용자 화면

첨부: `kaldi-note-design/docs/README.md` · `docs/DECISIONS.md` · `system/Design System.dc.html` · `screens/10 Brew First.dc.html`(같은 문법으로)

```
kaldi note의 「원두 상세」 화면을 만들어 주세요. 10 Brew First와 같은 원칙(한 화면에 한 가지, 숫자가 주인공, 아래쪽 큰 버튼 하나,
해요체 버튼·합니다체 기록 문장, 같은 모션 규격)을 그대로 따릅니다. 사진은 없습니다 — 사진 자리를 만들지 말고 글과 원장 행으로 정돈해 주세요.

[목적] 내가 쓰는 원두가 어떤 원두인지, 그리고 이 원두로 내가 어떻게 내렸는지를 보고, 다음 잔(「이 원두로 기록하기」)으로 이어지게 한다.
둘러보기 목록은 만들지 않습니다.

[들어오는 곳] ① 빠른 기록 「원두 고르기」 결과 행의 「정보」(시트 위에 한 장 더 쌓이는 시트) ② 기록 상세의 원두 행(페이지) ③ 오늘 홈 「지난번과 같게」 카드의 원두 이름

[데이터] (위 3절 그대로) 로스터, 이름, 싱글/블렌드, 배전도(5단계, 없을 수 있음)·Agtron·원문, 디카페인, 컵노트 원문 한 줄, 구매처 링크,
산지 0~N(국가·지역·농장·고도 범위·품종·가공·블렌드 비율). 내 기록 요약: 이 원두로 낸 잔 수, 평균 별점, 자주 쓴 비율과 원두량→물량, 최근 3개.

[그려 주세요]
- U1 원두 상세(모바일 페이지 + 시트형 1장, 웹 1440)
- U2 원두 고르기 결과 행 보강: 이름 · 로스터 · 배전도 점 · 산지 국가 · 디카페인 태그, 행 오른쪽 「정보」
[상태]
- 정보가 거의 없는 원두(이름·로스터만) — 빈 칸을 「정보 없음」으로 늘어놓지 말고 행을 감춘다
- 블렌드(산지 3개, 비율 표시) · 디카페인 · 배전도 원문만 있음("Light #92")
- 내 기록 0잔 — "아직 이 원두로 내린 기록이 없어요" + 「이 원두로 기록하기」
- 내가 직접 이름만 적어 만든 원두 — 이름과 내 기록만
- 카탈로그에서 숨겨진 원두를 기록에서 열었을 때 — 내 기록은 보이고 "카탈로그에서 내려간 원두예요" 한 줄
- 구매처 링크 없음 · 로딩 뼈대 · 불러오기 실패 · 다크 1장

[마지막에] 화면 폭별 바뀌는 점 표, 제가 정할 것 질문 목록(추천값·근거)
```

첨부: `docs/design/admin/README.md` · `docs/design/admin/design/Admin.dc.html` · `docs/design/admin/design-system-readme.md`

```
관리자 콘솔(Admin.dc.html)에 「원두」 메뉴 화면을 추가해 주세요. 기존 「장비」 화면의 문법(검색 + 필터 pill + 표 + 오른쪽 상세·편집 패널,
상태 미리보기 칩, 라이트/다크)을 그대로 따릅니다. 메뉴 위치는 카탈로그 묶음, 「원두 수집」 바로 아래.

[목적] 크롤러가 넣은 원두의 빠진 정보를 채우고, 확인하고, 잘못 수집된 것을 숨긴다. 사진은 없습니다.

[데이터] 위 3절 필드 + 새 값: 숨김, 수동 수정됨, 기록 수, 출처(크롤러 / 사용자 닉네임)

[그려 주세요]
- 목록: 검색(이름·로스터) / 필터 pill — 상태(확인 필요 · 확인됨 · 숨김), 출처(크롤러 · 사용자), 「정보 빠짐」(배전도 · 산지 · 가공 · 품종),
  로스터, 디카페인. 표 열: 이름 · 로스터 · 싱글/블렌드 · 배전도 · 산지 요약 · 상태 · 기록 수 · 수정일. 행 여러 개 선택 → 「확인 처리」·「숨기기」
- 상세·편집 패널: 기본(이름, 로스터 선택, 싱글/블렌드, 배전도 + Agtron + 원문, 디카페인), 컵노트, 구매 링크(열기),
  산지 행 추가/삭제(국가·지역·농장·고도 최소~최대·품종·가공·비율 — 블렌드면 비율 합 100 검사), 상태(확인됨 토글 · 숨김 토글),
  메타(출처, 생성·수정일, 「수동 수정됨 — 크롤러가 다시 수집해도 이름·링크 외에는 덮어쓰지 않아요」)
- 사용자 출처 원두: 「카탈로그로 올리기」 확인 흐름
- 원두 수집 실행 상세의 「매핑 못 한 원문」 행 → 「이 원두 편집」 → 패널이 열리고 해당 칸 강조
[상태] 결과 0 · 정보 빠짐 40건 이상 · 숨김 확인 대화상자 · 블렌드 비율 합 오류 · 마스터에 없는 가공(선택지에 없음 안내) · 저장 실패 · 긴 이름
[마지막에] 질문 목록(추천값·근거)
```

## 6. 11 Beans 시안 질문 10개 — 확정 (2026-11-15, 추천대로)

시안: `docs/design/kaldi-note-design/screens/11 Beans.dc.html`

| # | 결정 |
|---|---|
| 1 | 디카페인일 때만 칩 표시(「아님」 표시 없음) |
| 2 | 배전도 표시: 5단계 점 → (있으면) Agtron → 5단계가 없을 때만 원문 |
| 3 | 숨긴 원두도 원두 상세의 「이 원두로 기록하기」로는 기록 가능, 검색·최근 원두에서는 빠짐 |
| 4 | 「자주 쓴 비율」 = 최근 10잔 중 최빈값, 같으면 가장 최근 값 |
| 5 | 평균 별점은 별점 없는 기록 제외, 잔 수와 다르면 「★ 4.1 · 4잔 기준」 |
| 6 | 긴 컵노트는 2줄 말줄임, 누르면 펼침 |
| 7 | 고도 최소=최대이면 「1,750 m」 한 값 |
| 8 | 모바일에서 내 기록을 위로 올리지 않음(원두 정보 먼저, 진입 경로와 무관하게 같은 순서) |
| 9 | 직접 적은 원두 ↔ 카탈로그 원두 합치기는 이번에 안 함 |
| 10 | 구매처 링크는 확인 없이 새 탭, 끝에 ↗ (PWA는 시스템 브라우저) |

새로 필요한 값(API 없음): 내 기록 요약(잔 수 · 평균 별점 · 자주 쓴 비율 · 원두량→물량 · 최근 3개), 숨김 여부.
