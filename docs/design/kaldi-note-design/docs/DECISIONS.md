# 확정된 결정


다른 문서와 어긋나는 내용이 있으면 **이 문서가 우선**합니다.

## 1. 탭 이름 — 「내 잔」 확정

하단 탭: **홈 · 레시피 · 내 잔 · 더보기**

- 「기록」은 **동사로만** 씁니다 — “기록하기”, “기록을 저장했습니다”.
- 명사 자리에는 **「잔」** — “오늘의 한 잔”, “이번 주 6잔”, “142잔”.
- 웹 상단 바도 같습니다: 홈 · 레시피 · 내 잔.

이유: 「레시피」와 「기록」이 서로 구분되지 않는다는 문제를 절반만 해결하면 다시 헷갈립니다. 탭 이름까지 바꿔야 두 영역이 갈립니다.

## 2. 추천 배전도 — 3단계 확정

`recommendedRoastLevel: 'light' | 'medium' | 'dark'`

| 값 | 라벨 | 도트 색 |
|---|---|---|
| `light` | 약배전 | `oklch(0.72 0.05 60)` |
| `medium` | 중배전 | `oklch(0.62 0.06 55)` |
| `dark` | 강배전 | `oklch(0.4 0.05 45)` |

국내 로스터 표기가 대부분 3단계이고, 필터 pill도 3개까지가 한 줄에 들어갑니다. 5단계는 데이터가 쌓인 뒤 재검토합니다.

원두(Bean)의 실제 배전도와는 **별개 필드**입니다 — 레시피의 이 값은 “이 레시피에 어울리는 배전도”라는 권장값입니다.

## 3. 둘러보기 기본 정렬 — CURATED 우선 + 담김 순

```
ORDER BY is_curated DESC, saved_count DESC, created_at DESC
```

정렬 옵션은 `인기순`(기본) / `최신순` 두 개만 둡니다. 초기에는 공개 레시피가 적어서 최신순이 기본이면 화면이 비어 보입니다.

`is_curated`는 운영이 직접 지정하는 플래그입니다(사용자가 설정할 수 없음).

## 4. 「바로 내리기」 — 유지, 단 스냅샷 필수

남의 레시피를 담지 않고 한 번만 쓰는 경로는 **유지**합니다. 입문자가 매번 담기를 강요받으면 서랍이 금세 쓰레기통이 됩니다.

대신 그렇게 만들어진 잔은 원본 레시피를 참조하지 않고 **스냅샷을 자기 안에 박습니다**:

```ts
type Brew = {
  // ...
  recipeId: string | null;        // 내 서랍의 레시피로 내렸을 때만
  recipeSnapshot: {               // 항상 채움
    title: string;
    authorName: string;
    dose: number;
    water: number;
    temperature: number;
    grinder: string;
    grindValue: string;
    steps: Step[];
  };
}
```

이유:
- 원본이 수정·삭제돼도 내 잔의 기록은 변하지 않아야 합니다.
- 「레시피 / 실제」 비교표가 원본 API 호출 없이 성립합니다.
- 담아온 레시피도 같은 규칙을 씁니다(복제 시점 고정과 일관).

잔 상세에서 원본이 살아 있으면 `지연 님의 레시피 보기` 링크를 덧붙이고, 없으면 링크만 빼고 스냅샷으로 렌더합니다.

## 부가 — 수율(%) 처리

`수율 = TDS(%) × 음료 중량(g) / 원두량(g)`

TDS는 굴절계가 있어야 나오는 값이라 입문자에게는 대부분 빕니다. 규칙:

- TDS가 없으면 **계산하지 않고** 수율 자리를 비웁니다(`—`). 0이나 추정값을 넣지 마세요.
- 대표 수치 우선순위: **수율 → 별점**. 잔 목록·상세 모두 이 순서.
- 웹 테이블의 수율 열은 비어도 열 자체를 없애지 않습니다(정렬 유지).
- 안내 문구: `TDS가 없으면 수율을 계산할 수 없습니다.`
