# 기존 16화면 리스킨 스펙

> 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md) 참조.
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**

## 무엇을

**토큰만 바뀐 화면에 Clean Ledger의 레이아웃 어휘를 입힌다.**

`design-system-v2`가 색·서체·타입·모서리를 갈아끼웠지만 **배치는 그대로 뒀다.** 그래서 지금
화면은 「새 색으로 칠한 옛 구조」다. 디자인 핸드오프와 2026-09-17 목업이 공유하는 패턴 네 가지가
아직 코드에 하나도 없다.

| 패턴 | 지금 | 목업 |
|---|---|---|
| **히어로 카드** | 대표 수치가 그냥 큰 글자다 | 다크 블록 안에 아이브로우 + 36px 수치 + 구분선 + 서브메트릭 |
| **아이브로우 라벨** | 없음 | Mono 10px · `0.12em` · 대문자 · `ink-3` |
| **원장 행** | `dl`이 각자 다른 모양 | 위쪽 1px `divider` + 좌 라벨 / 우 값 |
| **섹션 제목** | `h2`가 `card-title`이긴 함 | 같음 — 유지 |

### 범위 밖 (Non-goals)

- **신규 화면.** 랜딩·오늘의 레시피·장비·관리자 화면은 각자의 스펙에서 만든다. 이 스펙은
  **이미 있는 16화면**만 다룬다.
- **신규 기능.** 「이 값으로 기록하기」·「다시 내리기」·기구 관리는 `small-features`다.
- **데스크톱 반응형.** 브레이크포인트는 `web-desktop`이 넣는다. 이번에도 모바일 폭 하나다.
- **비교표의 자연어 차이 문구.** 계산 로직이 붙는 일이라 `small-features`로 미룬다.
- **타입 스케일 확장.** `display`·`title`·`caption`·`label`은 **이번에도 넣지 않는다** —
  쓸 자리가 생기는 것은 웹 화면과 타이머다(`AC-DS2-13`이 죽은 단계를 막는다).

## 왜

**지금 화면은 디자인과 절반만 같다.** 색과 글꼴은 맞는데 구조가 옛것이라, 새로 그린 목업 7개를
붙이는 순간 **같은 앱 안에서 두 가지 문법이 섞인다.** 신규 화면을 먼저 만들면 그 불일치가
사용자에게 그대로 보인다 — 그래서 방향 문서가 리스킨을 신규 화면보다 앞(2단계)에 뒀다.

그리고 **카드 7곳이 `Card` 프리미티브를 쓰지 않고 클래스를 직접 들고 있다.** `design-system-v2`가
컨트롤(버튼·입력)만 걷어냈고 면(面)은 남겨뒀다. 남은 채로 신규 화면을 만들면 그 7곳이 영구히
예외로 굳는다.

## 용어

| 용어 | 정의 |
|---|---|
| 히어로 카드 | 화면의 대표 수치를 담는 다크 블록. `data-hero`가 표시한다 |
| 아이브로우 | 히어로/섹션 위의 Mono 대문자 라벨. `data-eyebrow`가 표시한다 |
| 원장 행 | 라벨-값 한 줄. 위쪽 1px `divider`를 갖는다. `MetricRow`가 낸다 |

## 데이터

스키마·API 변경 없음. 프론트 마크업만 바뀐다.

## 기존 AC 갱신

**히어로 도입이 대표 수치의 구조를 바꾼다.** 지금까지 대표 수치는
`<dl data-lead>` 안의 `sr-only` 라벨 + 값이었다. 목업은 그것을 **아이브로우(보이는 라벨) +
판 위의 수치**로 바꾼다. 그래서 대표 수치의 모양을 리터럴로 들고 있던 AC들이 함께 움직인다.

**AC ID는 유지하고 값만 바꾼다.** `design-system-v2` 때와 같은 방식이다.

| AC | 그때 | 지금 | 왜 |
|---|---|---|---|
| `AC-CONSIST-08`·`09`·`10` | `dl > dt.sr-only + dd`, 텍스트가 `"비율1:16.7"` | `Hero`의 아이브로우 + 값 | **라벨이 더는 `sr-only`가 아니다** — 목업이 보이는 10px Mono 라벨로 쓴다 |
| `AC-CONSIST-03`·`04` | 메타줄 `gap-x-3`(12px) | 히어로 안 2열 그리드 `gap-x-4` | 판 안에서는 한 줄 나열이 아니라 격자다 |
| `AC-CONSIST-07` | 메타줄 라벨이 `ink-3` | `on-hero-dim` | 어두운 판 위에서는 `ink-3`가 읽히지 않는다 |
| `AC-READ-13` | 굵기 600, 자간 `-0.72px` | 굵기 **500**, 자간 **`-1.44px`** | 핸드오프가 `metric-hero`를 「Mono 36 / 500 / −4%」로 정의한다 |
| `AC-READ-15` | 라벨이 `ink-3` | 히어로 밖은 그대로, 안은 `on-hero-dim` | 위와 같은 이유 |
| `AC-STRUCT-17`·`18` | `data-lead` 텍스트로 1:비율 확인 | 같은 확인, **새 DOM 구조에서** | 값의 규칙은 그대로다 |

**「화면마다 대표 수치 하나」는 그대로다.** 바뀐 것은 그것을 담는 그릇이지 규칙이 아니다.

## 어떻게 동작 — 인수 조건

### 구조

#### AC-SKIN-01 · 모든 화면이 같은 Shell을 쓴다

- **Given** `frontend/src` 아래의 모든 화면 컴포넌트
- **When** 최상위 `main` 요소의 클래스를 모은다
- **Then** `mx-auto w-full max-w-2xl px-6 py-6`을 공통으로 갖는 형태가 **1종**이다
  (`flex flex-col gap-6`은 그 위에 얹는 변형으로 허용한다)

#### AC-SKIN-02 · 면이 Card 프리미티브를 쓴다

- **Given** `src/components/ui` 밖의 모든 `.tsx`
- **When** `rounded-surface`를 직접 쓴 곳을 찾는다
- **Then** **0곳**이다 — 카드·다이얼로그는 `Card`를 쓴다

#### AC-SKIN-03 · 대표 수치가 히어로 카드 안에 있다

- **Given** 대표 수치를 가진 화면(`/recipes/[id]`·`/brews/[id]`·`/gear/grind-converter`)
- **When** `data-lead` 요소의 조상을 거슬러 올라간다
- **Then** `data-hero`를 가진 요소가 있다

#### AC-SKIN-04 · 히어로 카드는 라이트·다크 모두 어둡다

- **Given** 히어로 카드(`data-hero`)
- **When** 라이트 모드에서 배경색을 잰다
- **Then** `paper`보다 어둡다 — **모드와 무관하게 항상 어두운 블록이다**

#### AC-SKIN-05 · 아이브로우가 Mono 대문자다

- **Given** `data-eyebrow` 요소
- **When** 계산된 `font-family`·`text-transform`·`letter-spacing`을 읽는다
- **Then** `IBM Plex Mono`이고 `uppercase`이며 자간이 `0`보다 크다

### 컴포넌트

#### AC-SKIN-06 · 프리미티브에 Hero·Eyebrow가 있다

- **Given** `src/components/ui`
- **When** 내보내는 컴포넌트를 읽는다
- **Then** `Hero`와 `Eyebrow`가 존재한다

#### AC-SKIN-07 · MetricRow가 원장 행 형태다

- **Given** `MetricRow`를 렌더한 결과
- **When** 계산된 `border-top`을 읽는다
- **Then** 1px 실선이고 색이 `divider` 토큰이다

### 회귀 — 이것이 깨지면 리스킨이 실패한 것이다

#### AC-SKIN-08 · `data-*` 훅이 그대로다

- **Given** `frontend/src` 전체
- **When** `data-lead`·`data-compare`·`data-diff`·`data-empty`를 센다
- **Then** 각각 **1곳 이상** 남아 있다

#### AC-SKIN-09 · 모든 화면의 터치 타깃이 44×44 이상이다

- **Given** 기존 16화면 전부
- **When** 누를 수 있는 요소의 렌더 크기를 잰다
- **Then** 전부 44px 이상이다

#### AC-SKIN-10 · 가로 스크롤이 없다

- **Given** 뷰포트 360px에서 16화면 전부
- **When** `document.documentElement.scrollWidth`를 읽는다
- **Then** **360 이하**다

#### AC-SKIN-11 · 서버가 준 문구를 가공하지 않는다

- **Given** 분쇄도 환산 경고와 프로필 관계 문구
- **When** 렌더된 텍스트를 API 응답과 대조한다
- **Then** 그대로다 — 리스킨이 문구를 바꾸지 않는다

## 열어둔 결정

- **히어로 카드를 쓸 화면의 정확한 목록.** 지금은 대표 수치가 있는 셋으로 잡았으나,
  목록 화면의 카드(`RecipeCard`·`BrewLogCard`)까지 히어로로 만들지는 구현 중 눈으로 보고 정한다.
  **목록에 다크 블록이 여러 개 쌓이면 무거워질 수 있다.**
