# 0009. 공개 서비스 전환(R1)을 보류하고 "둘이 쓰는 도구"를 1부로 삼는다

## 맥락

`docs/design/2026-09-16-product-direction.md`(결정 1)는 1차 사용자를 "불특정 다수 공개
서비스"로 바꿨다. 그런데 2026-09-23 시점에 그 방향 아래 스펙 9개가 전부 UI·시각 작업이었고,
정작 공개 전환에 필요한 콘텐츠 파이프라인·공개 인가·SEO는 스펙조차 없었다. 계획이 두 갈래
(product-direction의 12단계 vs JOURNAL의 ①~⑩)로 갈라진 채 가장 눈에 띄는 것부터 손대고
있었다.

## 결정

**공개 서비스 전환을 보류한다.** 1부는 `docs/design/2026-08-14-architecture.md`가 원래
못박았던 성공 기준 — **「우리 둘이 실제로 매일 쓴다」** — 로 되돌아간다. 레시피 서랍(M1)이
콘텐츠 채우기보다 먼저다. `product-direction.md`의 결정 2~16(제휴 수익 구조, 콘텐츠 수집
방식, 디자인 핸드오프 채택 등)은 **폐기가 아니라 유효하며**, 2부 재개 시 그대로 쓴다.

## 결과

- 로드맵(`docs/ROADMAP.md`)의 1부 M1~M4가 지금의 유일한 계획 출처다. 2부(P1~P3)는 보류 상태로
  남아 있다.
- `AC-RECIPESBREWS-54`(비로그인 `GET /recipes` = 401)처럼 "공개 전환을 전제로 한 미래 변경"이
  예고돼 있던 항목은 지금 구현을 그대로 두고, 2부 재개 시 교체될 것이라는 주석만 남긴다.
- 재개 조건은 사용자가 정한다. 재개하지 않은 채 이 문서를 뒤집는 제안(예: 지금 공개 인가부터
  만들자)은 먼저 사람에게 확인받는다.
