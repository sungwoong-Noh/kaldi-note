# 역할

너는 **작은 결함 하나를 고치는 중**이다. 대상: $ARGUMENTS

이 커맨드는 `docs/conventions/workflow.md`의 **갈래 B(시각 보정)·C(버그·잔손질)** 전용이다.
새 스펙도, 새 계획 문서도 만들지 않는다. 갈래 A(백엔드·데이터·도메인 숫자·권한에 조금이라도
닿는 것)라고 판단되면 **여기서 멈추고 `/interview`로 넘어가라고 알려라.**

# 0단계: 갈래 확정

- **인자가 이슈 번호면** `gh issue view <번호>`로 라벨(`lane:B`/`lane:C`)과 본문을 읽는다.
- **한 줄 설명이면** 아래로 판정한다.

| 신호 | 갈래 |
|---|---|
| 목업(`docs/design/`)과 배포 화면이 다르다 | **B** — 목업이 곧 스펙 |
| 기존 스펙의 AC를 위반하는 동작(테스트가 있었어야 하는데 없었거나, 있는데 깨졌다) | **C** |
| 스펙에 없던 동작을 새로 요구한다 | **A 아님.** 여기서 멈추고 `/interview`로 안내하라 |
| 도메인 숫자(반올림·환산·인가 규칙)가 바뀐다 | **A 아님.** 마찬가지 |

애매하면 **A로 넘겨라.** 이 커맨드에서 임의로 A를 처리하지 않는다.

# B 갈래 — 시각 보정

1. 관련 목업(`docs/design/`, 스크린샷 또는 `.dc.html`)을 찾는다.
2. 배포/로컬 화면을 실제로 렌더해 **목업과 나란히 대조**한다 — 텍스트로 "다를 것 같다"고
   추측하지 않는다.
3. 디자인 토큰(색·타입·간격·모서리) **밖으로 나가는 값을 새로 만들지 않는다.** 기존 토큰 중
   가장 가까운 것을 쓰거나, 토큰 자체가 부족하면 멈추고 사람에게 확인받는다.
4. 고친다. 기존 e2e/유닛 테스트가 있으면 통과하는지 확인한다 — 시각 보정은 보통 새 테스트를
   만들지 않는다(색·크기 회귀는 기존 테스트가 이미 잡는다).
5. **반나절을 넘기면 멈춘다.** 남은 부분은 다음 마일스톤의 A 스펙으로 넘긴다고 보고하라.

# C 갈래 — 버그·잔손질

1. **깨진 AC를 먼저 찾는다.** 어느 스펙의 어느 AC가 위반됐는지 `docs/specs/`에서 확인한다.
   못 찾으면 그건 버그가 아니라 새 기능이다 — A로 전환하라고 알린다.
2. **그 AC를 재현하는 실패 테스트를 먼저 쓴다.** 실행해서 실제로 빨간지 확인한다.
3. 최소 구현으로 고친다. 테스트가 초록이 되는지 확인한다.
4. 근본 원인을 고친다 — 증상만 가리는 패치가 아니라, 그 함수의 모든 호출자에 적용되는 수정인지
   확인한다.

# 공통 — 마무리

1. 검증을 돌린다: `docs/conventions/workflow.md`「완료 정의」의 코드(A·C) 또는 시각 보정(B)
   항목.
2. `docs/GOTCHAS.md`에 남길 만한 함정을 발견했으면 추가한다.
3. 커밋(`fix/<이름>` 브랜치, `docs/conventions/git.md` 형식)하고 PR을 연다 — B/C도 PR을
   거친다. 본문에 이슈를 `Closes #N`으로 연결한다.
4. CI가 초록이면 셀프 머지한다(`docs/conventions/git.md`「머지 규칙」).

# 어조

간결하게. 스펙·계획 문서를 새로 쓰려는 충동이 들면 그건 이 커맨드의 범위를 벗어났다는 신호다.
