# 결정 기록 (ADR)

**되돌리기 어려운 설계 결정**을 남기는 곳. "왜 이렇게 만들었는가"를 코드에서 되짚을 수 없을 때 쓴다.

시각 보정처럼 되돌리기 쉬운 것, 스펙 하나로 끝나는 것은 여기 오지 않는다 — `docs/specs/`가 담당한다.

---

## 작성 규칙

- 파일명: `NNNN-<slug>.md`. 번호는 **4자리, 순차 증가**. 한 번 부여하면 바꾸지 않는다.
- 템플릿: [`TEMPLATE.md`](TEMPLATE.md).
- `status`는 셋 중 하나다.

| status | 의미 |
|---|---|
| `유효` | 지금도 따른다 |
| `보류` | 폐기는 아니지만 지금 실행하지 않는다 (재개 조건을 본문에 적는다) |
| `대체됨` | 다른 ADR이 뒤집었다. `supersededBy`에 그 번호를 적는다 |

## 대체 규칙

결정이 뒤집히면 **새 ADR을 추가**한다. 기존 ADR의 본문은 고치지 않고 `status: 대체됨` +
`supersededBy: NNNN`만 바꾼다. 대체 이유는 새 ADR의 「맥락」에 적는다.

## 삭제하지 않는다

**스펙과 ADR은 삭제하지 않는다** (`docs/conventions/workflow.md` 「문서 수명」). 결정이 틀렸더라도
"한때 이렇게 정했었다"는 기록 자체가 값어치가 있다 — 다음에 같은 논의가 돌아왔을 때 처음부터
다시 하지 않으려면 이전 결정과 그 근거가 남아 있어야 한다.
