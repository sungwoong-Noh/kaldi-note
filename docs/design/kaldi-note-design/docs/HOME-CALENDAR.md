# 홈 화면 개편 — 달력 (Home v3)

> 이 문서는 `design_handoff_kaldi_note/README.md`의 **M1 · 홈** 섹션을 대체합니다.
> 디자인 파일: `Kaldi Note Home - Calendar.dc.html` (모바일 — C1 = 내 기록, C2 = 팔로우 선택, SPEC = 규격 패널)
> 디자인 파일: `Kaldi Note Home - Calendar Web.dc.html` (웹 — CW1 = 내 기록, CW2 = 팔로우 선택 + 빈 날짜)
>
> 아래 규격은 **모바일 기준**입니다. 웹에서 달라지는 부분은 맨 끝 「웹 (1440×900)」 절에 모아 두었습니다.

## 왜 바뀌었나

기존 홈은 "가장 최근 기록 하나"를 크게 보여줬습니다. 바뀐 홈은 **언제 내렸는지**를 보여줍니다 — 달력에서 기록이 있는 날엔 점이 찍히고, 날짜를 누르면 그날의 기록 목록이 달력 아래에 나옵니다. 상단 팔로우 레일에서 사람을 바꾸면 같은 달력이 그 사람의 기록으로 갈아끼워집니다.

원칙: **빈 날을 채우거나 위로하지 않습니다.** 연속 기록일·스트릭·배지·칭찬 문구는 두지 않습니다. 빈 날이 많다는 사실 자체가 사용자에게 필요한 정보입니다.

## 화면 구조 (위 → 아래)

```
상태바(목업 장식, 구현 X)
헤더           로고만. 아바타는 팔로우 레일의 「나」와 중복이므로 제거
팔로우 레일     가로 스크롤, 아바타 50px
월 헤더        2026.09 + 건수 + ‹ › 네비
요일 헤더       월 화 수 목 금 토 일
달력 그리드     7열 × 5~6행, 셀 44px
──────────── 1px divider
날짜별 목록     선택된 날짜의 기록 (← 이 영역만 스크롤)
CTA            이 레시피로 내렸다
탭 바          홈 · 레시피 · 기록 · 더보기
```

**스크롤 정책**: 화면 전체가 아니라 **날짜별 목록 영역만** 세로 스크롤합니다. 헤더 · 레일 · 달력 · CTA · 탭 바는 고정입니다. 기록이 3~4건인 날에도 달력이 밀려 올라가지 않아야 합니다.

## 팔로우 레일

| 항목 | 값 |
|---|---|
| 아바타 | 50px, radius 999 |
| 라벨 | 11.5px, 아바타 아래 gap 7px |
| 항목 간 gap | 14px |
| 선택 상태 | 아바타에 2px `ink` 링(`box-sizing: border-box`) + 라벨 weight 600 `ink` |
| 비선택 | 링 없음 + 라벨 weight 400 `ink-3` |
| 마지막 칸 | 1px dashed `oklch(0.82 0.01 75)` 원 + mono `+`, 라벨 "찾기" → 사용자 검색 |

규칙:
- 첫 칸은 **항상 「나」**, 기본 선택 상태.
- 한 번에 **한 사람만** 선택합니다. 여러 명을 겹쳐 보는 모드는 넣지 않습니다 — 점이 누구 것인지 모호해집니다.
- **맞팔로우인 사람만** 레일에 나타납니다. 한쪽만 팔로우한 관계는 기록을 볼 수 없으므로 레일에서도 뺍니다.
- 가로 스크롤. 스크롤바는 숨기고, 잘린 다음 항목이 살짝 보이도록 우측 패딩 24px를 유지합니다.

## 달력 그리드

| 항목 | 값 |
|---|---|
| 레이아웃 | `grid-template-columns: repeat(7, 1fr)`, `row-gap: 4px` |
| 셀 높이 | 44px (히트 타깃 최소치) |
| 주 시작 | **월요일** |
| 요일 헤더 | mono 10px / letter-spacing 0.08em / uppercase / `oklch(0.58 0.02 70)` (토·일은 `oklch(0.62 0.02 70)`) |
| 날짜 숫자 | mono 14px |
| 첫 주 빈칸 | 같은 높이의 빈 `div` (`height: 44px`) |

### 날짜 색 (명도만)

| 상태 | 색 |
|---|---|
| 이번 달 지난 날 · 평일 | `oklch(0.3 0.015 60)` |
| 이번 달 지난 날 · 주말 | `oklch(0.5 0.015 60)` |
| 미래 · 평일 | `oklch(0.72 0.012 70)` |
| 미래 · 주말 | `oklch(0.78 0.012 70)` |

**토·일에 파랑·빨강을 쓰지 않습니다.** 팔레트의 유채색은 에스프레소 계열 하나뿐이고, 여기에 요일색이 들어오면 아래의 기록 점 신호가 묻힙니다. 주말 구분은 명도로만 합니다.

### 기록 점

| 항목 | 값 |
|---|---|
| 색 | **`oklch(0.55 0.16 30)`** — 시스템에 추가되는 유일한 신호색 |
| 크기 | 5px 원 |
| 위치 | 날짜 숫자 아래, gap 5px (선택된 날은 gap 4px) |
| 기록 없는 날 | 같은 크기의 **투명 자리를 그대로 둡니다** (`background` 없음) — 숫자 baseline이 흔들리지 않게 |

그날 기록이 몇 건이든 **점은 항상 1개**입니다. 건수는 달력 아래 목록 헤더에서 셉니다. 점의 크기·개수·농도로 빈도를 표현하지 않습니다.

### 선택 / 오늘

- **선택된 날**: 숫자를 28px `ink` 원으로 감싸고 텍스트를 `oklch(0.97 0.004 85)` weight 500으로. 점은 원 아래 그대로 유지.
- **오늘인데 선택 안 됨**: 28px 원에 1px `border` 링만(배경 없음), 숫자 색은 기본값.
- 화면 진입 시 **오늘이 자동 선택**됩니다. 월을 넘기면 그 달의 1일이 아니라 **선택 없음** 상태로 두고, 목록 영역에는 그 달의 최근 기록일을 보여주지 않습니다 — 날짜를 눌러야 목록이 채워집니다.
- 기록이 1건뿐인 날을 눌러도 **상세로 바로 보내지 않습니다.** 항상 목록에 1행으로 표시합니다(동작 일관성).

### 월 네비게이션

- 좌측: `2026.09` mono 22px weight 500 letter-spacing −0.03em + 그 달의 건수 라벨 (`9 BREWS`, 남의 달력이면 `지연 · 6 BREWS`).
- 우측: 32×32 / 1px `border` / radius 7 버튼 두 개 (`‹` `›`).
- 좌우 스와이프로도 월을 넘길 수 있게 합니다.
- **미래 달로는 넘어가지 않습니다** — 다음 달 버튼은 현재 달에서 비활성(`oklch(0.78 0.012 70)`).

## 날짜별 목록

헤더: mono 10px / 0.16em / uppercase / `ink-3` — `09.19 SAT · 2 BREWS`. 남의 달력이면 이름을 끼웁니다: `09.19 SAT · 지연 · 1 BREW`.

행 = 기존 **원장 행** 컴포넌트 그대로:
- 좌측 9px roast dot
- 레시피명 14.5px weight 500 (1줄 ellipsis) + 시각·별점 캡션 11.5px `ink-3`
- 우측 대표 수치 mono 14px — 내 기록은 **수율**(`20.4 %`), TDS가 없으면 비율(`1:15.6`)
- 상단 1px divider, 마지막 행에만 하단 divider
- 행 탭 → `/brews/[id]`

빈 상태(그 날짜에 기록 없음): 한 줄만.
```
이 날에는 기록이 없습니다.
```
`surface` 배경 + 왼쪽 2px `oklch(0.85 0.01 75)` 보더 + radius `0 8px 8px 0` / 13.5px. 버튼이나 일러스트를 붙이지 않습니다.

## 내 달력 vs 남의 달력

| | 내 달력 | 남의 달력 |
|---|---|---|
| 월 헤더 라벨 | `9 BREWS` | `지연 · 6 BREWS` |
| 목록 헤더 | `09.19 SAT · 2 BREWS` | `09.19 SAT · 지연 · 1 BREW` |
| 목록 하단 | — | 관계 문구 블록(서버 문구 그대로): "맞팔로우 상태여서 지연 님의 기록이 보입니다." |
| CTA | **primary** `이 레시피로 내렸다` | **secondary** `이 레시피로 내리기` |

남의 달력에서는 기록을 수정·삭제할 수 없고, 레시피는 포크 후 사용합니다.

## 데이터

### 달력 조회

```
GET /api/calendar?userId={me|followeeId}&month=2026-09
→ {
    month: "2026-09",
    totalCount: 9,
    days: [ { date: "2026-09-02", count: 1 }, { date: "2026-09-05", count: 2 }, ... ]
  }
```

`days`에는 **기록이 있는 날만** 담습니다(희소 배열). 클라이언트는 이 날짜 집합으로 점을 찍습니다. `count`는 점 렌더에 쓰지 않고, 목록 헤더의 건수 프리필과 프리페치 판단에만 씁니다.

### 날짜별 기록

```
GET /api/brews?userId={...}&date=2026-09-19
→ [ { id, recipeTitle, brewedAt, rating, yield, ratio, roastLevel }, ... ]
```

`yield`가 `null`(TDS 미입력)이면 우측 수치는 `ratio`로 대체합니다.

### 팔로우 레일

```
GET /api/follows/mutual
→ [ { id, name, initials, avatarTone }, ... ]
```

`avatarTone`은 warm 뉴트럴 3종 중 하나의 인덱스입니다 — 사용자별로 고정되어야 합니다(매번 랜덤 X).

## 상태 & 캐싱

```
selectedUserId  // 기본: 내 id
selectedMonth   // 'YYYY-MM', 기본: 이번 달
selectedDate    // 'YYYY-MM-DD' | null, 기본: 오늘
```

- 캐시 키는 `(userId, month)`. 월을 앞뒤로 오갈 때 재요청하지 않습니다.
- 사용자를 바꾸면 `selectedMonth`는 유지하고 `selectedDate`는 초기화(오늘이 그 달에 있으면 오늘, 아니면 null).
- **낙관적 반영**: 새 기록을 저장하면 서버 응답 전에 해당 날짜에 점을 찍고 목록에 행을 추가합니다. 실패 시 되돌리고 에러 토스트.
- 월 전환은 프리페치: 현재 달을 로드할 때 이전 달도 함께 받아 둡니다.
- 달력 로딩 중에는 점만 비우고 **그리드 골격은 그대로** 둡니다(레이아웃 점프 방지). 스켈레톤 블록을 깔지 않습니다.

## 접근성

- 각 날짜 셀은 `button`, `aria-label="9월 19일, 기록 2건"` / 기록 없으면 `"9월 19일, 기록 없음"`.
- 선택된 셀에 `aria-current="date"`.
- 점은 장식이므로 `aria-hidden` — 정보는 label 텍스트로 전달합니다.
- 팔로우 레일은 `role="tablist"`, 각 아바타 `role="tab"` + `aria-selected`. 날짜별 목록이 대응하는 `tabpanel`입니다.
- 좌우 화살표 키로 날짜 이동, 위아래로 주 단위 이동.

## 웹 (1440×900)

같은 데이터·같은 규칙이고, 공간을 더 쓰는 만큼 셀과 목록의 밀도가 달라집니다.

### 레이아웃

```
상단 바        로고 + 홈·레시피·기록 + primary CTA + 아바타       (고정)
팔로우 레일     상단 바 아래 가로 전폭, 1px divider              (고정)
├─ 좌측 flex:1   월 헤더 → 요일 헤더 → 달력 그리드 (남는 높이 전부)
└─ 우측 420px   선택 날짜 헤더 → 기록 카드 (이 영역만 스크롤) → 맥락 CTA
```

좌측 padding `32px 40px 32px 48px`, 우측 컬럼 padding 좌우 40px · 배경 `surface` · `flex: none`.

### 달력 셀

모바일이 44px 정사각 셀이라면, 웹은 **박스**입니다 — 남는 세로 높이를 5행(또는 6행)이 `1fr`로 나눠 갖습니다.

| 항목 | 값 |
|---|---|
| 그리드 | `grid-template-columns: repeat(7, minmax(0,1fr))` + `grid-template-rows: repeat(5, minmax(0,1fr))` |
| 격자선 | 1px `oklch(0.93 0.008 80)`, 그리드 상단만 `divider-strong` |
| 셀 padding | 9px 10px |
| 날짜 숫자 | mono 13px (색 규칙은 모바일과 동일) |
| 기록 점 | 숫자 **오른쪽** 6px 간격, 5px `signal-record` |
| 요약 줄 | 레시피명 11.5px `oklch(0.45 0.015 60)`, 1줄 ellipsis |
| 2건 이상 | 요약 줄 아래 `외 N건` 11px `oklch(0.6 0.02 70)` |
| 다른 달 칸 | 내용 없이 `oklch(0.975 0.006 82)` 배경 |

요약은 **최대 2줄(레시피명 + 외 N건)까지만** 입니다. 기록을 셀 안에 쌓아 올리지 않습니다 — 그건 우측 컬럼의 일입니다.

**행 수**: 달이 6주에 걸치면 `repeat(6, minmax(0,1fr))`로 바꿔 셀 높이를 줄입니다. 그리드 영역 전체 높이는 항상 같아야 하고, 월을 넘길 때 레이아웃이 튀면 안 됩니다.

### 선택 / 오늘 (웹)

- **선택된 셀**: 셀 전체에 `box-shadow: inset 0 0 0 2px oklch(0.22 0.015 60)` + 배경 `oklch(0.96 0.006 82)`. 숫자는 24px `ink` 원 + 흰 텍스트. 요약 줄은 weight 500 `oklch(0.3 0.015 60)`으로 한 단 진하게.
- **오늘인데 선택 안 됨**: 숫자를 24px 원 + 1px `border` 링으로만.
- 셀 전체가 클릭 영역입니다.

### 팔로우 레일 (웹)

가로 pill 형태 — 아바타 32px + 이름 13.5px을 한 줄에 둡니다.

| 상태 | 스타일 |
|---|---|
| 선택 | `background: ink` pill (padding `6px 14px 6px 6px`, radius 999) + 이름 weight 600 `oklch(0.97 0.004 85)` |
| 비선택 | 배경 없음 + 이름 `oklch(0.45 0.015 60)` |
| 찾기 | 1px dashed 원 + mono `+`, 앞에 1px 세로 divider(높이 24px)로 구분 |

모바일의 2px 링 대신 **채운 pill**을 씁니다 — 가로 배치에서는 링이 약해 선택 상태가 읽히지 않습니다.

### 우측 컬럼

헤더: 요일 아이브로우(`SATURDAY`, 남의 달력이면 `FRIDAY · 지연`) + 날짜 26px weight 600 + 우측에 건수 mono 12px.

기록은 원장 행이 아니라 **카드**입니다(공간이 있으니 태그와 메모까지 보여줍니다):
- `paper` 배경 + 1px `border` + radius 10 + padding 20 + gap 13
- 상단: roast dot 10px + 레시피명 15.5px 600 + 원두·기구·시각 캡션 12px / 우측 대표 수치 mono 17px
- 1px divider 아래 태그 줄 — 비율(accent-wash) · 온도 · 시간 · 별점
- 메모가 있으면 13px italic 한 줄

그 아래 Observation 블록(있을 때만), 하단에 **선택 날짜 맥락 CTA**:

| | CTA |
|---|---|
| 내 달력 | primary `이 날짜로 기록 추가` |
| 남의 달력 | secondary `지연 님 프로필 보기` |

상단 바의 CTA(`이 레시피로 내렸다`)는 전역 액션이고, 우측 하단 CTA는 선택된 날짜에 종속된 액션입니다 — 둘은 다른 일을 합니다.

빈 날짜: `이 날에는 기록이 없습니다.` 한 줄만(모바일과 동일 스타일, radius `0 10px 10px 0`).

### 반응형 분기

| 폭 | 레이아웃 |
|---|---|
| ≥ 1100px | 좌측 달력 + 우측 420px 2컬럼 |
| 760–1099px | 1컬럼 — 달력 아래에 선택 날짜 목록이 붙습니다(달력 셀은 웹 박스 유지) |
| < 760px | 모바일 레이아웃 — 셀 44px 정사각, 점만, 요약 줄 없음 |

## 디자인 시스템에 추가되는 토큰

| Token | 값 | 용도 |
|---|---|---|
| `signal-record` | `oklch(0.55 0.16 30)` | 달력의 기록 점 — **이 용도 외에는 쓰지 않습니다** |

다크 모드에서는 `oklch(0.65 0.17 30)`으로 한 단계 밝힙니다.
