# 앱 셸 스펙

> 2026-09-01 `/interview`로 확정. 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md).
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**

## 무엇을

**화면 사이를 오갈 수단을 만든다.** 지금은 로그인하면 `/recipes`에 떨어지는데 거기서 홈으로도 `/brews`로도 갈 수 없다. 하단 탭바 넷(`홈`·`레시피`·`기록`·`더보기`)을 깔아 최상위 화면을 잇고, 작성·편집 화면에는 `취소`를 달아 빠져나올 길을 낸다.

**로그아웃할 수 있게 한다.** API는 프론트·백엔드 모두 있는데 그것을 부르는 버튼이 없어 한 번 로그인하면 나갈 수가 없다. `더보기` 화면에 내 정보와 함께 둔다.

**기록할 수 없는 레시피에서 기록 버튼을 감춘다.** 백엔드는 `POST /brew-logs`가 **본인 소유 레시피만** 받는데(`BrewLogService.requireOwnedRecipe`), 화면은 시드 레시피에도 `이 레시피로 내렸다`를 보여줘 누르면 403이 난다.

**브루잉 로그 화면의 빠진 조각을 채운다.** `WEBBREW` 스펙의 「폼의 라벨과 값」 표가 요구한 `드로다운 시간`·`음료 중량`·`TDS` 입력칸이 구현되지 않았다. 그래서 추출 수율이 영원히 계산되지 않고, 상세의 추출 분석 영역도 나타날 수 없다.

**분쇄도 환산기 화면을 만든다.** 환산 API는 있으나 부르는 화면이 없다. 마스터 그라인더 목록끼리 환산한다.

### 범위 밖 (Non-goals)

1. **`/beans`(원두 재고)·`/gear`(내 장비) 목록 화면.** IA 사이트맵이 예정한 화면이지만 이번에는 환산기만 만든다. `더보기`에 링크를 얹을 자리는 생기므로 각각의 스펙에서 화면만 만들면 된다.
2. **작성 화면 이탈 확인 대화상자.** `취소`는 명시적 행동이라 곧바로 나간다. 임시저장이 없어 값은 사라지지만, 확인 단계를 두면 이번 분량이 늘고 탭바를 작성 화면에서 뺀 것으로 이미 오조작은 막았다.
3. **프로필 수정·회원 탈퇴.** 백엔드에 API가 없다.
4. **데스크톱 전용 레이아웃.** 하단 탭바를 넓은 화면에서도 그대로 쓴다.
5. **공동 레시피 편집.** 레시피는 `ownerUserId` 단독 소유이고 공유는 읽기 전용이다. 남의 레시피로 기록하려면 포크한다 — 아키텍처의 핵심 시나리오가 그 흐름이다.
6. **`Holzklotz E80`의 「변경 전」 사양.** 제조사 대응표에 두 사양이 있으나 「변경 후」만 넣는다. 다른 사양의 기기가 나타나면 **별도 모델 행**으로 추가한다.

## 왜

**앱에 들어가면 나올 수도, 돌아다닐 수도 없다.** 2026-09-01 운영 환경에서 실제로 확인된 것들이다 — 로그인 후 `/recipes`에 도착하면 그게 끝이다. 홈에 최근 기록 3개를 만들어뒀지만 홈으로 가는 길이 없어 주소를 직접 쳐야 하고, 로그아웃 버튼은 어디에도 없다.

**시드 레시피로 기록을 시작할 수 없다.** 이 앱에서 가장 흔한 사용은 "큐레이션된 Kasuya 4:6대로 내리고 기록"인데, 그 버튼을 누르면 `본인의 레시피만 브루잉 로그에 연결할 수 있습니다`라는 403이 돌아온다. 포크라는 정답이 있는데 화면이 그리로 안내하지 않는다.

**리프랙토미터를 사도 쓸 데가 없다.** TDS 입력칸이 없어 `extractionYieldPercent`·`strengthZone`·`extractionZone`이 전부 계산되지 않는다. "추출 수율을 추적한다"는 이 서비스의 존재 이유 하나가 화면상 닫혀 있다.

### 환산 계수의 근거

**제조사가 배포한 스텝-마이크론 대응표(「변경 후」 사양)에서 그대로 나온다.** 다섯 점이 오차 없이 선형이다.

| Step | 제조사 표 | `(setting − 0) × 22.50` |
|---|---|---|
| 10 | 225µm | 225µm |
| 20 | 450µm | 450µm |
| 30 | 675µm | 675µm |
| 40 | 900µm | 900µm |
| 50 | 1,125µm | 1,125µm |

`zeroPointOffsetClicks`는 **`0`** 이다 — 원점을 지나는 정비례라 보정이 없다.

**제조사 표에는 「변경 전」 사양도 함께 있다**(같은 기울기 22.50에 120µm 오프셋, `zeroPointOffset = -5.33`). 사용자 기기가 「변경 후」임을 확인해 그쪽을 채택했다. 두 사양은 30스텝에서 795µm와 675µm로 갈리므로, 다른 사양의 기기가 나타나면 **별도 모델 행으로 추가한다** — 같은 행을 고치면 기존 로그의 `actualGrindMicronEstimated` 해석이 소급해서 바뀐다.

환산 결과는 언제나 추정치다(「뒤집으면 안 되는 결정」 3번). 제조사도 *"기기마다 약간의 차이가 있을 수 있습니다"* 라고 명시한다.

## API

**새 API는 없다.** 전부 기존 엔드포인트를 부른다.

| 메서드 | 경로 | 인증 | 이 스펙에서의 쓰임 |
|---|---|---|---|
| GET | `/api/v1/users/me` | 필요 | `더보기`의 닉네임·이메일·가입일 |
| POST | `/api/auth/logout` | — | 로그아웃 (Next 라우트 핸들러) |
| GET | `/api/v1/gear/grinders` | 필요 | 환산기의 그라인더 선택 |
| POST | `/api/v1/gear/grind-conversions` | 필요 | 환산 |
| POST | `/api/v1/brew-logs` | 필요 | 추가된 세 입력칸의 값이 실린다 |

## 화면

| 경로 | 인증 | 탭바 | 하는 일 |
|---|---|---|---|
| `/more` | 필요 | O | 내 정보, 로그아웃, 분쇄도 환산기 링크 |
| `/gear/grind-converter` | 필요 | O | 그라인더 간 분쇄도 환산 |
| `/`·`/recipes`·`/brews` 및 상세 | 필요 | O | (기존) |
| `/recipes/new`·`/recipes/[id]/edit`·`/brews/new` | 필요 | **X** | (기존) + `취소` 버튼 |
| `/login`·`/auth/callback` | 불필요 | **X** | (기존) |

### 탭바의 라벨과 경로

**테스트는 이 문자열로 찾는다.**

| 라벨 | `href` | 활성 판정 |
|---|---|---|
| `홈` | `/` | 경로가 정확히 `/` |
| `레시피` | `/recipes` | `/recipes`로 시작 |
| `기록` | `/brews` | `/brews`로 시작 |
| `더보기` | `/more` | `/more`로 시작 |

홈만 접두사 판정을 쓰지 않는다 — `/`는 모든 경로의 접두사라 그렇게 하면 항상 켜진다.

### 더보기의 표시 항목

| 라벨 | 값 | 없을 때 |
|---|---|---|
| `닉네임` | `me.nickname` | 항상 있다 |
| `이메일` | `me.email` | **그 줄을 그리지 않는다** |
| `가입일` | `me.createdAt`의 앞 10자 (`2026-08-21`) | 항상 있다 |

### 작성 화면의 `취소` 목적지

| 화면 | 이동 |
|---|---|
| `/recipes/new` | `/recipes` |
| `/recipes/[id]/edit` | `/recipes/[id]` |
| `/brews/new?recipeId=N` | `/recipes/N` |

### 로그 목록 카드

```
Kasuya 4:6                                ★ 4
2026-08-31 · 1:15.0 · 92°C · 3:30 · 20.5 %
```

둘째 줄은 `날짜 · 비율 · 물온도 · 추출시간 · 추출수율`이고 **값이 없는 항목은 자리째 뺀다.** 구분자는 ` · `다. 표시 함수는 레시피 카드가 쓰는 `formatRatio`·`formatTemperature`·`formatDuration`을 그대로 쓴다 — 같은 값이 두 화면에서 다른 모양으로 보이면 안 된다.

### 브루잉 로그 작성 — 추가되는 입력칸

`WEBBREW` 스펙의 「폼의 라벨과 값」 표에 있으나 구현되지 않은 셋이다. 전부 선택 항목이고 초기값은 빈칸이다.

| 라벨 | 필드 | 타입 |
|---|---|---|
| `드로다운 시간` | `actualDrawdownSeconds` | 정수 |
| `음료 중량` | `beverageWeightG` | 소수 |
| `TDS` | `tdsPercent` | 소수 |

## 어떻게 동작 — 인수 조건

### 탭바

#### AC-WEBSHELL-01 · 탭 네 개가 순서대로 보인다

- **Given** 로그인한 사용자가 `/recipes`를 연다
- **When** 화면을 확인한다
- **Then** 이름이 `홈`·`레시피`·`기록`·`더보기`인 링크가 그 순서로 있다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx`

#### AC-WEBSHELL-02 · 각 탭이 제 경로를 가리킨다

- **Given** 탭바가 그려져 있다
- **When** 각 링크의 `href`를 읽는다
- **Then** `홈`은 `/`, `레시피`는 `/recipes`, `기록`은 `/brews`, `더보기`는 `/more`다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx`

#### AC-WEBSHELL-03 · 로그 상세에서도 기록 탭이 켜진다

- **Given** 현재 경로가 `/brews/42`다
- **When** 탭바를 확인한다
- **Then** `기록` 링크의 `aria-current`가 `page`이고, 나머지 세 링크에는 `aria-current`가 없다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx`

#### AC-WEBSHELL-04 · 레시피 편집에서도 레시피 탭이 켜진다

- **Given** 현재 경로가 `/recipes/12/edit`다
- **When** 탭바를 확인한다
- **Then** `레시피` 링크의 `aria-current`가 `page`다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx`

#### AC-WEBSHELL-05 · 홈은 정확히 일치할 때만 켜진다

- **Given** 현재 경로가 `/recipes`다
- **When** 탭바를 확인한다
- **Then** `홈` 링크에 `aria-current`가 **없다**
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx`

#### AC-WEBSHELL-06 · 로그인 화면에는 탭바가 없다

- **Given** 세션이 없다
- **When** `/login`을 연다
- **Then** 이름이 `기록`인 링크가 화면에 없다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx` (경로를 `/login`으로 주입)

> 탭바는 `app/layout.tsx`에 있고 **경로를 보고 스스로 숨는다.** 페이지 테스트는 레이아웃을 렌더하지 않아 "없다"가 자동으로 통과해버리므로, 부재 검증은 탭바 자신의 테스트에서 한다.

#### AC-WEBSHELL-07 · 작성 화면에는 탭바가 없다

- **Given** 로그인한 사용자다
- **When** `/brews/new?recipeId=1`을 연다
- **Then** 이름이 `기록`인 링크가 화면에 없다
- **검증** 컴포넌트 테스트 `BottomNav.test.tsx` (경로를 `/brews/new`로 주입)
