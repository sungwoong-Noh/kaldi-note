# 0001. Recipe(설계도)와 BrewLog(실행 기록)를 분리한다

## 맥락

레시피(이렇게 내릴 것)와 실제로 내린 기록(이렇게 내렸다)을 하나의 테이블로 합치자는 제안이
반복해서 나온다 — 필드가 거의 겹치기 때문이다.

## 결정

**둘을 분리한다.** `Recipe`는 설계도이고 `BrewLog`는 실행 기록이다. 같은 레시피를 여러 번
내렸을 때 결과 차이를 추적하는 것이 이 서비스의 존재 이유이므로, 합치면 그 추적이 불가능해진다.

## 결과

- 같은 `recipeId`로 여러 `BrewLog`를 쌓고 비교할 수 있다.
- 레시피 조회와 기록 조회가 별도 API·화면으로 갈린다 — 사용자가 "설계"와 "결과"를 헷갈리지
  않도록 UI에서도 명확히 구분한다(`frontend/CLAUDE.md`).
- 이 결정을 뒤집는 제안은 요구사항 위반으로 취급한다. 되돌리려면 먼저 사람에게 확인받는다.
