# 레시피 / 잔 — 구조 개편

> 디자인 파일:
> - `Kaldi Note Recipes vs Brews - Web.dc.html` — 결정 패널 4개 + 웹 4화면(RW1 둘러보기 / RW2 내 서랍 / RW3 레시피 상세 / BW1 내 잔)
> - `Kaldi Note Recipes vs Brews - Mobile.dc.html` — 모바일 6화면(RM1 내 서랍 / RM2 둘러보기 / RM3 필터 시트 / RM4 레시피 상세 / RM5 담기 직후 편집 / BM1 내 잔)
>
> 이 문서는 README의 「레시피」·「기록」 관련 절을 **대체**합니다. 색·타입·간격 토큰은 README를 그대로 따릅니다.

## 왜 바꿨나

사용자 테스트에서 나온 문제 다섯 개:

1. 웹과 모바일이 똑같아서 웹에서 공간이 낭비된다.
2. 레시피 화면과 기록 화면이 비슷해서 지금 어디 있는지 헷갈린다.
3. 「레시피」와 「기록」이라는 말이 서로 구분되지 않는다.
4. 「포크」가 무슨 동작인지 모른다.
5. 레시피 목록에 전체가 다 떠서 내 것이 안 보인다. 검색도 없다.

## 결정 01 — 용어

| 개념 | 표기 | 성격 |
|---|---|---|
| Recipe | **레시피** | 앞으로 이렇게 내리겠다는 지침. 반복 가능, 날짜 없음, 공유 가능 |
| Brew | **잔** | 실제로 내린 한 번. 날짜에 묶임, 1회성, 수정은 되지만 복제는 안 됨 |

규칙:
- **「기록」은 동사로만 씁니다** — “기록하기”, “기록을 저장했습니다”.
- **명사 자리에는 「잔」** — “오늘의 한 잔”, “이번 주 6잔”, “142잔”.
- 하단 탭 3번째 이름은 **「내 잔」** (기존 「기록」).
- 레시피 화면에서 “기록”이라는 단어가, 잔 화면에서 “레시피”라는 단어가 **같은 무게로 나오지 않게** 합니다. 레시피 카드의 “21잔 기록”처럼 보조 정보로만 등장.

> 논의 여지: 「내 잔」이 과하게 느껴지면 탭만 「기록」으로 두고 본문 카피에서만 「잔」을 쓸 수 있습니다. 단, 그러면 문제 3이 절반만 해결됩니다.

## 결정 02 — 레이아웃으로 구분

같은 데이터 밀도를 **다른 형태**로 씁니다. 이것이 두 화면을 구분하는 주된 장치입니다.

| | 레시피 | 잔 |
|---|---|---|
| 웹 | **4열 카드 그리드** — 고르는 화면 | **테이블** — 날짜순으로 쌓이는 장부 |
| 모바일 | **1열 카드** | **2줄 원장 행** |
| 대표 수치 | 원두량 (mono 36px) | 원두량 (행/셀 안 mono 14px) |
| 정렬 | 인기순 / 최신순 | 날짜 내림차순 고정 |
| 시간 표현 | 없음 | 날짜가 첫 열 |

카드는 “무엇을 쓸까”를 묻고, 테이블은 “언제 무엇을 했나”를 답합니다. 카드에 날짜를 넣거나 테이블을 카드로 바꾸면 이 구분이 무너집니다.

## 결정 03 — 포크 폐기, 「내 서랍에 담기」

「포크」를 버립니다. 새 라벨은 **「내 서랍에 담기」**.

흐름:

1. 남의 레시피 상세에서 **「내 서랍에 담기」** (primary)
2. 바로 복제하지 않고 **편집 화면으로 이동** — 상단에 출처 배너가 붙은 채로 열립니다:
   > 지연 님의 「아침에 마시는 밝은 워시드」를 가져왔습니다. 내 원두와 기구로 고친 뒤 저장하세요.
3. 저장하면 내 서랍에 들어가고, 카드·상세에 `지연 님 레시피에서` 배지가 남습니다.

편집 화면을 한 번 거치는 이유: 남의 레시피는 그 사람의 원두·기구 기준이라 그대로는 쓸 수 없습니다. **고치는 자리가 곧 설명**입니다. 편집 화면에서 값을 바꾸면 원본 값을 옆에 같이 보여줍니다(`16 g` / `원본 15 g`, accent 색 mono 11.5px).

규칙:
- 출처 배지는 목록 카드와 상세 양쪽에 **영구히** 남습니다.
- 원본이 나중에 수정돼도 내 것은 따라가지 않습니다 — **복제 시점 고정**.
- 내가 만든 레시피에는 `내가 만든` 배지(accent-wash) + `N잔 기록` 카운트.
- 「바로 내리기」는 담지 않고 이번 한 번만 쓰는 경로로 유지합니다(secondary).

## 결정 04 — 레시피 탭을 둘로

탭 「레시피」 안에서 세그먼티드로 나눕니다. **기본값은 내 서랍**입니다.

| 세그먼트 | 내용 |
|---|---|
| **내 서랍** (기본) | 내가 만든 것 + 담아온 것. 바로 내릴 수 있는 것만. 필터 pill: `전체 N` / `내가 만든 N` / `담아온 N` |
| **둘러보기** | 검색 + 필터 + 공개 레시피 전체. 마켓처럼 고르는 곳 |

전체가 섞여 뜨던 기존 구조를 이것으로 대체합니다.

### 검색

- 대상: 레시피 이름, 원두 이름, 로스터, 기구.
- 웹: 헤더 우측 420px 입력 + `⌘K` 힌트. 모바일: 세그먼티드 아래 전폭 입력.
- 결과 건수를 항상 표시합니다(`128개 · 인기순`).
- 결과 없음: `찾는 레시피가 없나요? / 검색어를 줄이거나 필터를 해제해 보세요.` (점선 카드, 그리드 마지막 셀)

### 필터

필터 항목 4종:

| 항목 | 값 |
|---|---|
| 온도 | HOT / ICE (단일 선택) |
| 추천 배전도 | 약배전 / 중배전 / 강배전 (다중 선택) |
| 원두량 | 10–30 g 범위 슬라이더(듀얼 핸들) |
| 기구 | V60 / Kalita / Origami / Clever (다중 선택) |

- **웹**: 헤더 아래 pill 줄로 전부 펼칩니다. 선택 = 채운 pill(ink) 또는 accent-wash pill.
- **모바일**: **바텀시트**. 닫힌 상태에서는 `필터 N` + 적용된 값만 요약 pill로 보여줍니다. 시트 하단 CTA는 `N개 결과 보기`.
- 배전도 도트는 필터 pill 안에서도 씁니다(7–9px).

> 배전도 단계는 **3단계**로 잡았습니다. 5단계(약·약중·중·중강·강)로 갈지는 원두 데이터가 어떻게 들어오는지에 달려 있습니다 — 로스터 표기가 3단계면 3단계로 두는 게 맞습니다.

## 결정 05 — 카드 항목 교체

레시피 카드에서 비율·온도·시간을 빼고 다음 3개로 바꿉니다.

| 항목 | 표현 |
|---|---|
| **원두량** | 대표 수치. mono 36px / weight 500 / −4% / lh 1 (`15 g`) |
| **Hot / Ice** | HOT = 채운 칩 `background: ink` + `paper` 텍스트 / ICE = 1px `oklch(0.35 0.015 60)` 외곽선 + `ink` 텍스트. 둘 다 mono 10.5px / +8% / radius 3 / padding 5px 9px |
| **추천 배전도** | 로스트 도트 9px + 라벨 12.5px (`약배전`) |

고를 때 먼저 묻는 건 “몇 그램 쓰지?”이기 때문에 원두량이 대표 수치가 됩니다. 비율·온도·시간은 상세의 히어로로 내려갑니다.

카드에 4개 이상 수치를 넣지 마세요 — 고르는 데 방해가 됩니다.

### 카드 구성

```
제목 17px 600            [CURATED]      ← 배지는 있을 때만
원두량 mono 36px
[HOT]  ● 약배전
─────────────────────    ← 1px divider
아바타 22px  작성자 · 담김 42            ← 둘러보기
또는  [지연 님 레시피에서]                ← 내 서랍 · 담아온 것
또는  [내가 만든] 21잔 기록                ← 내 서랍 · 내가 만든 것
```

웹은 padding 22 / gap 16, 모바일은 padding 17px 18px / gap 13. **모바일에서는 원두량과 (HOT + 배전도)를 같은 줄 양끝에** 둡니다 — 세로로 쌓으면 카드가 너무 길어집니다.

## 화면별 명세

### RW1 · 웹 레시피 둘러보기

상단 바 → 헤더(아이브로우 `BROWSE` + 제목 30px + 세그먼티드 280px, 우측에 검색 420px) → 필터 pill 줄(1px divider로 닫음) → 4열 카드 그리드 `repeat(4, minmax(0,1fr))` gap 18.

필터 줄 우측 끝에 결과 건수 mono 12px. pill 사이 세로 divider(높이 20px)로 온도/배전도/수치 그룹을 나눕니다.

### RW2 · 웹 내 서랍

RW1과 같은 골격. 다른 점:
- 아이브로우 `MY DRAWER · 7`, 제목 「내 서랍」
- 검색 입력 없음 → 우측에 소유 필터 pill 3개(`전체 7` / `내가 만든 4` / `담아온 3`)
- 카드 하단이 작성자 줄 대신 **출처/소유 배지**

### RW3 · 웹 레시피 상세

상단 바 CTA는 secondary `내 서랍에 담기`(우측 컬럼 하단에 primary로 한 번 더).

좌측 flex:1 — CURATED 배지 + `RECIPE` 아이브로우 → 제목 32px → 작성자 줄(아바타 26px + `42명이 담았습니다`) → 설명 15px/1.75 max 64ch → **스텝 테이블**.

스텝 테이블 열: `# 40px` / `타입 90px` / `메모 flex` / `물량 100px 우측` / `시간 90px 우측`. 타입 배지는 블룸만 accent-wash, 나머지는 sunken.

우측 420px(`surface`) — 히어로(대표 = **원두량 44px**, 아래 HOT 칩 + `약배전 권장`, divider 아래 물량/비율/온도) → 원장 dl(기구 / 분쇄도 / 총 시간) → Observation(담기 안내) → 하단 CTA 2개(`내 서랍에 담기` primary + `이 레시피로 바로 내리기` secondary).

### BW1 · 웹 내 잔

상단 바 CTA `기록하기`. 헤더(`MY CUPS · 2026` + 제목 30px, 우측 기간·별점 필터 pill + 총 건수) → **통계 4칸**(이번 달 / 평균 별점 / 가장 많이 쓴 원두량 / 즐겨 쓴 레시피) → 테이블.

테이블 열: `날짜 108px` / `레시피 · 원두 flex` / `원두량 100px` / `온도 90px` / `시간 90px` / `수율 100px` / `평가 70px` — 날짜 외 전부 우측 정렬. 레시피 열은 roast dot 10px + 레시피명 14.5px + 원두·기구 캡션 12px 2줄. TDS가 없으면 수율 칸은 `—` (`oklch(0.62 0.02 70)`).

요일은 날짜 뒤에 `oklch(0.6 0.02 70)`로 한 톤 연하게.

### RM1 · 모바일 내 서랍

헤더(`MY DRAWER · 7` + 제목 27px + 아바타) → 세그먼티드 → 소유 필터 pill 가로 스크롤 → 1열 카드 → `더 보기` → CTA `새 레시피` → 탭 바.

### RM2 · 모바일 둘러보기

헤더 → 세그먼티드 → 검색 입력 전폭 → **필터 요약 줄**(`필터 2` ink pill + 적용값 accent-wash pill, 우측에 건수) → 1열 카드 → 탭 바. CTA 없음(둘러보기는 만드는 화면이 아님).

### RM3 · 모바일 필터 바텀시트

배경 화면 `opacity: 0.35`, 시트는 radius `18px 18px 0 0` + 상단 1px border + 그랩바 40×4.

섹션 순서: 온도(2분할) → 추천 배전도(3분할, 선택은 accent-wash + 1px accent 보더) → 원두량(듀얼 핸들 슬라이더, 우측에 현재 범위 mono 13px) → 기구(칩 4개) → CTA `N개 결과 보기`.

헤더에 「필터」 19px + 우측 `초기화` 13.5px.

### RM4 · 모바일 레시피 상세

뒤로 / CURATED → `RECIPE` 아이브로우 + 제목 24px + 작성자 줄 → 히어로(원두량 36px + HOT + `약배전 권장` + 4칸 dl) → 스텝 원장 행 5개 → CTA 2개(`내 서랍에 담기` primary / `바로 내리기` secondary) → (탭 바 없음).

### RM5 · 모바일 담기 직후 편집

상단 바: 취소 / `내 서랍에 담기` / 저장(accent) → **출처 배너**(Observation 스타일, 출처 문장) → 히어로(원두량 36px + `원본 15 g` 대비, 원두/물 입력 칩 2개) → 원장 입력 행(제목 / 온도+스테퍼 / 기구 / 분쇄도) → 스텝 에디터(합계 검증 포함) → CTA `내 서랍에 저장`.

값을 바꾼 항목은 **원본 값을 옆에 병기**합니다(accent 계열 mono 11.5px).

### BM1 · 모바일 내 잔

헤더(`MY CUPS · 142` + 제목 27px + 아바타) → **통계 2칸**(이번 달 / 평균 별점) → 기간 필터 pill → **2줄 원장 행** → `더 보기` → CTA `기록하기` → 탭 바.

2줄 원장 행 구조:
```
● (roast dot 10px)  레시피명 15px 500          원두량 mono 14px
                    09.19 토 · 92°C · 2:45    20.4 % · ★ 4
```
둘째 줄 우측은 accent 색 mono 11.5px. 수율이 없으면 `★ 4`만.

## 데이터 모델 변경

`Recipe`에 추가:

| 필드 | 타입 | 비고 |
|---|---|---|
| `temperatureType` | `'hot' \| 'ice'` | 필수. 카드·필터에서 사용 |
| `recommendedRoastLevel` | `'light' \| 'medium' \| 'dark'` | 필수. 원두의 실제 배전도와 별개 — “이 레시피에 어울리는” 값 |
| `sourceRecipeId` | `string \| null` | 담아온 원본 id |
| `sourceAuthorName` | `string \| null` | 배지 표기용(비정규화 — 원본 삭제 후에도 배지가 남아야 함) |
| `savedCount` | `number` | `담김 N` |
| `brewCount` | `number` | `N잔 기록` |

`Brew`는 변경 없음. 다만 목록 API가 `dose`를 항상 포함해야 합니다(대표 수치가 됐으므로).

검색/필터 쿼리 파라미터: `q`, `temp`, `roast[]`, `doseMin`, `doseMax`, `dripper[]`, `sort`(`popular` | `recent`), `scope`(`drawer` | `public`), `owner`(`all` | `mine` | `saved`).

## 남은 결정

→ **모두 `DECISIONS.md`에서 확정되었습니다.** 아래는 당시 열려 있었던 질문 기록이며, 구현 시에는 `DECISIONS.md`를 보십시오.

1. 탭 이름을 「내 잔」으로 확정할지, 「기록」 유지할지.
2. 배전도 3단계 / 5단계.
3. 둘러보기 기본 정렬 — 인기순(담김 수) vs 최신순. 초기에는 데이터가 적으니 **CURATED 우선 + 담김 순**을 권합니다.
4. 「바로 내리기」를 남길지. 담지 않고 내린 잔은 어떤 레시피에 묶일지 애매해집니다 — 잔에 `recipeSnapshot`을 박아 두는 방식이 필요합니다.
