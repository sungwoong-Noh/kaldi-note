## 1. 레시피 작성·편집 — `/recipes/new`, `/recipes/[id]/edit`

**참고 목업:** `Kaldi Note Recipes vs Brews - Web.dc.html`(RW3 레시피 상세), `Recipes vs Brews - Mobile.dc.html`(RM4·RM5), `screens-v2/BrewNew.dc.html`(폼 패턴)

```
[화면] 레시피 작성·편집. 새로 만들기와 편집이 같은 화면입니다. 편집은 제목에 「레시피 수정」, 저장 버튼 문구만 다릅니다.
이 서비스의 핵심은 레시피를 "푸어 스텝 시퀀스"로 구조화해서 재현 가능하게 만드는 것입니다. 스텝 편집이 이 화면의 중심입니다.

[데이터 — 입력 필드와 제약]
기본
- 제목 title: 필수, 최대 100자
- 설명 description: 선택, 최대 2000자
- 공개 범위 visibility: PRIVATE(나만) / FRIENDS(맞팔로우 친구) / PUBLIC(전체)
수치
- 원두량 doseG: 필수, 1.0–200.0 g
- 물 waterG: 필수, 10.0–3000.0 g
- 비율 ratio: 자동 계산(물÷원두, 소수 1자리, "1:15.6") — 입력 아님, 대표 수치 후보
- 물 온도 waterTempC: 선택, 60.0–100.0 °C
- 총 시간 totalTimeSeconds: 선택, 1–3600초 (m:ss로 표시)
- 온도 타입 temperatureType: HOT / ICE
- 권장 배전도 recommendedRoastLevel: LIGHT / MEDIUM / DARK
장비 (시스템 카탈로그에서 선택)
- 드리퍼 brewerId (브랜드·이름), 필터 filterId (이름·재질), 그라인더 모델 grinderModelId (브랜드·이름)
- 분쇄도 grindSettingValue + 단위 grindSettingUnit: CLICK(클릭) / NUMBER(눈금) / MICRON(마이크론)
- 저장 후 서버가 grindMicronEstimated(추정 마이크론)를 돌려줍니다. "추정치"로만 표시합니다 — 확정값처럼 보이면 안 됩니다.
스텝 (0–30개, 순서 있음)
- 종류 stepType: BLOOM(뜸) / POUR(붓기) / WAIT(대기) / SWIRL(돌리기) / STIR(젓기) / DRAWDOWN(배출)
- 시작 startAtSeconds: 0–3600, 지속 durationSeconds: 0–3600
- 물 waterG: 선택, 0–3000 g
- 붓는 방식 pourTechnique: CENTER / SPIRAL / PULSE / EDGE (선택)
- 교반 agitation: NONE / SWIRL / STIR (선택)
- 메모 note: 최대 500자

[웹에서 원하는 것]
좌측은 폼, 우측 420px 사이드 컬럼에는 스텝 타임라인 미리보기와 대표 수치(비율)를 둡니다. 입력하는 동안 실시간으로 반영됩니다.

[모바일에서 원하는 것]
한 컬럼 세로 스크롤. 스텝 추가·편집을 인라인으로 할지 바텀시트로 할지 제안해 주세요(둘 다 그려도 됩니다).

[추가 상태]
- 스텝 0개 / 스텝 30개(추가 버튼 비활성)
- 검증 에러: 원두량 0, 물 3000 초과, 제목 비움 — 첫 에러 필드로 포커스가 이동합니다(이미 구현된 규칙)
- 편집 중 나가기 확인
- 친구 레시피를 포크한 레시피를 편집할 때 「원본: ○○ 님의 레시피」 표시

[질문 후보]
스텝 물량 합계와 총 물량이 다르면 경고할지, 스텝 순서 변경 방식(드래그 vs 위/아래 버튼).
```

## 2. 프로필 — `/u/[id]`

**참고 목업:** `Kaldi Note Home - Calendar.dc.html` · `Home - Calendar Web.dc.html`(팔로우 레일·아바타 3색조·관계 문구)

```
[화면] 다른 사용자의 프로필. 초대 링크(/u/{id})로 들어오는 첫 화면이기도 합니다. 여기서 팔로우하고, 맞팔로우가 되면 서로의 기록이 보입니다.

[데이터]
- 사용자: id, nickname, profileImageUrl(없을 수 있음 → 아바타 3색조 이니셜)
- 팔로우 상태: following(내가 팔로우) · followedBy(상대가 나를) · mutual(맞팔로우)
- 관계 문구 — 아래 문자열을 그대로 씁니다(바꾸지 않음):
  · 맞팔로우: "맞팔로우 상태여서 {닉네임} 님의 기록이 보입니다."
  · 내가만 팔로우: "상대도 나를 팔로우하면 서로의 기록이 보입니다"
  · 상대만 팔로우: "나를 팔로우하고 있습니다"
  · 둘 다 아님: (문구 없음 또는 제안)
- 버튼: 팔로우 / 팔로우 취소

[지금 없는 것 — 그리려면 「API 없음」 라벨]
팔로워·팔로잉 수, 이 사람의 레시피 목록, 최근 기록. 맞팔로우일 때 무엇을 보여주면 좋을지 제안해 주세요. 공개 범위 규칙: 레시피는 PRIVATE(나만)·FRIENDS(맞팔로우)·PUBLIC(전체) 세 가지입니다.

[웹] 1440에서 프로필 한 장만 가운데 떠 있으면 비어 보입니다. 좌측 프로필 + 우측 내용 구조를 제안해 주세요.

[추가 상태]
- 관계 4가지 각각
- 내 프로필을 볼 때(팔로우 버튼 대신 무엇을 보여줄지 — 예: 초대 링크 복사)
- 존재하지 않는 사용자(404)
- 팔로우 요청 처리 중
- 닉네임이 아주 길 때, 프로필 이미지가 없을 때
```

## 4. 내 기구 관리 (신규) — 제안 경로 `/more/gear`

**참고 목업:** `Kaldi Note Screens - Mobile.dc.html`(M8 분쇄도 환산기)

```
[화면] 내가 가진 그라인더를 등록·관리하는 화면입니다. 분쇄도 환산기와 기록 작성에서 "내 그라인더"를 고를 때 이 목록을 씁니다. 더보기에서 들어옵니다.
드리퍼·필터는 시스템 카탈로그뿐이고 사용자 소유 개념이 없으므로, 이번 범위는 그라인더만입니다.

[데이터 — 내 그라인더 한 개]
- 브랜드 brand, 모델명 grinderModelName
- 클릭당 마이크론 micronsPerClick
- 별칭 nickname: 선택, 최대 50자
- 영점 보정 calibrationOffsetClicks(클릭 수, 소수 가능)
- 기본 그라인더 isDefault(하나만)

[추가 — 모델 선택]
시스템 그라인더 모델 목록에서 고릅니다. 각 모델: brand, name, adjustmentType, 최소·최대 눈금(minSetting·maxSetting), burrType, convertible(환산 가능 여부).
convertible=false인 모델은 환산기에서 쓸 수 없습니다 — 선택은 되지만 「환산 불가」가 보여야 합니다.
등록 입력은 모델 + 별칭 두 가지뿐입니다.

[수정·삭제]
별칭 변경, 영점 보정 변경, 기본 지정, 삭제 — API는 다음 마일스톤에서 추가합니다. 화면은 이것까지 포함해서 그려 주세요.

[추가 상태]
- 0개(빈 상태 — 첫 그라인더 등록으로 유도)
- 1개 / 10개 이상
- 모델 검색 결과 없음
- 기본 그라인더를 삭제하려 할 때
- 삭제 확인
- 별칭이 아주 길 때

[질문 후보]
영점 보정을 이 화면에서 직접 입력할지, 환산기에서 "내 값이 이 정도였다"로 역으로 맞출지.
```
