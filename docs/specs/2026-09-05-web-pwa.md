# PWA 설치와 레시피 오프라인 스펙

> 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md) 참조.
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**

## 무엇을

앱을 **폰 홈화면에 설치할 수 있게** 하고, **한 번이라도 연 레시피 상세를 네트워크 없이 다시 열 수 있게**
한다. 매니페스트와 아이콘을 두어 브라우저가 설치 대상으로 인식하게 하고, `public/sw.js`를 직접 써서
레시피 상세 응답을 네트워크 우선으로 캐시한다. 네트워크가 없을 때는 `/offline` 화면이 **캐시에 실제로
들어 있는 레시피만** 목록으로 보여준다.

### 범위 밖 (Non-goals)

- **브루잉 로그의 오프라인 큐잉.** 작성은 온라인 필수다. 사진 업로드가 있고, 나중에 올리는 큐를 만들
  만큼의 요구가 없다(`frontend/CLAUDE.md`가 YAGNI로 이미 잘라둔 것을 그대로 따른다).
- **사진(첨부) 캐시.** 용량이 크고 레시피 재현에 필요하지 않다.
- **레시피 목록(`/recipes`) 캐시.** 목록에는 뜨는데 상세는 캐시에 없는 항목이 섞여 「눌러도 안 열리는
  줄」이 생긴다. 도달 경로는 `/offline`이 대신한다.
- **설치 유도 배너.** `beforeinstallprompt`를 가로채 자체 배너를 띄우지 않는다. 브라우저 기본 설치
  경로만 쓴다.
- **푸시 알림·백그라운드 동기화.** Service Worker가 생기면 할 수 있게 되지만 쓸 곳이 없다.
- **홈(`/`)·기록(`/brews`)의 오프라인 동작.** 이번에 캐시하는 데이터는 레시피 상세뿐이다.

## 왜

부엌에서 젖은 손으로 폰을 쓴다. 지금은 **브라우저 탭으로만 열 수 있고**, 홈화면에 설치할 수 없다.
매니페스트가 없어 브라우저가 설치 대상으로 인식하지 않는다 — `frontend/public/`에는 Next 기본 SVG
넷뿐이다.

더 큰 문제는 **네트워크가 끊기면 아무것도 못 본다**는 것이다. 추출은 3분 30초 동안 스텝을 여섯 번 밟는
일인데, 그 사이 앱을 잘못 닫거나 새로고침하면 다시 열 방법이 없다.

그리고 지금 구조에서는 **오프라인이면 로그인 화면으로 튕긴다.** `useRequireSession.ts:54`가
`refreshSession()`의 실패 원인을 가리지 않고 무조건 `/login`으로 보내기 때문이다. 캐시를 아무리 잘
쌓아도 이 한 줄이 있는 한 오프라인에서는 레시피에 도달할 수 없다.

## 용어

| 용어 | 정의 |
|---|---|
| 앱 셸 | 화면을 그리는 데 필요한 문서·스크립트·스타일. 레시피 데이터는 포함하지 않는다 |
| 레시피 캐시 | 레시피 상세 API 응답을 담는 Cache Storage. 이름은 `kaldi-recipe-v1` |
| 콜드 스타트 | 홈화면 아이콘이나 새로고침으로 앱을 처음부터 여는 것. accessToken이 메모리에 없다 |
| 네트워크 실패 | `fetch`가 응답을 못 받고 예외로 끝나는 것. HTTP 응답을 받은 401과 구분한다 |

## 데이터

스키마 변경 없음. 백엔드는 한 줄도 건드리지 않는다.

브라우저 Cache Storage만 쓴다.

| 캐시 이름 | 담는 것 | 상한 | 만료 |
|---|---|---|---|
| `kaldi-shell-v1` | 앱 셸(문서·`/_next/static/*`)과 `/offline` | 없음 | 없음 |
| `kaldi-recipe-v1` | `GET {API}/api/v1/recipes/{id}` 응답 | **50개** | **없음** |

`kaldi-recipe-v1`이 50개를 넘으면 **가장 오래전에 넣은 항목부터** 지운다.

## API

새 API 없음. 기존 `GET /api/v1/recipes/{id}`의 응답을 Service Worker가 가로채 캐시할 뿐이다.

### 매니페스트

`public/manifest.json`으로 둔다.

```json
{
  "name": "kaldi note",
  "short_name": "kaldi note",
  "description": "커피 레시피를 재현 가능한 형태로 기록하고 공유합니다.",
  "lang": "ko",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#ffffff",
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "/icons/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

아이콘은 **검은 바탕(`#171717`)에 흰 소문자 `k`** 다. SVG로 그려 PNG로 내린다.

### 오프라인 화면 문구

| 자리 | 문구 |
|---|---|
| 제목 | `연결 없음` |
| 본문 | `네트워크에 연결되어 있지 않습니다. 저장된 레시피는 볼 수 있습니다.` |
| 빈 목록 | `저장된 레시피가 없습니다` |

### 인증 실패의 분기

`refreshSession()`은 지금 성공 시 토큰, 실패 시 falsy를 돌려준다. **실패 원인을 구분해 돌려주도록
넓힌다.**

| 상황 | 판정 | 화면 |
|---|---|---|
| `fetch`가 예외로 끝난다 | 네트워크 실패 | `/login`으로 보내지 않는다 |
| HTTP 401을 받는다 | 인증 만료 | `/login?next=<현재 경로>` |

## 어떻게 동작 — 인수 조건

### 정상 동작 — 설치

#### AC-PWA-01 · 매니페스트가 열린다

- **Given** 프로덕션 빌드가 떠 있다
- **When** `GET /manifest.json`
- **Then** HTTP `200`이고 `Content-Type`이 `application/manifest+json`이다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-02 · 이름이 `kaldi note`다

- **Given** `/manifest.json`의 본문
- **When** JSON으로 읽는다
- **Then** `name`과 `short_name`이 모두 `kaldi note`다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-03 · 독립 실행 창으로 열린다

- **Given** `/manifest.json`의 본문
- **When** JSON으로 읽는다
- **Then** `display`가 `standalone`이고 `start_url`이 `/`다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-04 · 색이 흰색이다

- **Given** `/manifest.json`의 본문
- **When** JSON으로 읽는다
- **Then** `theme_color`와 `background_color`가 모두 `#ffffff`다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-05 · 아이콘 셋이 실제로 열린다

- **Given** `/manifest.json`의 본문
- **When** `icons`를 읽고 각 `src`를 요청한다
- **Then** 항목이 **3개**이고 `192x192`(any)·`512x512`(any)·`512x512`(maskable)이며, 세 요청 모두 HTTP `200`에 `Content-Type`이 `image/png`다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-06 · 문서가 매니페스트를 가리킨다

- **Given** `/recipes`를 연다
- **When** HTML을 읽는다
- **Then** `<link rel="manifest" href="/manifest.json">`이 정확히 1개 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-07 · Service Worker 파일이 열린다

- **Given** 프로덕션 빌드가 떠 있다
- **When** `GET /sw.js`
- **Then** HTTP `200`이고 `Content-Type`이 `text/javascript`다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-08 · Service Worker가 등록된다

- **Given** `/recipes`를 연다
- **When** `navigator.serviceWorker.ready`를 기다린다
- **Then** `navigator.serviceWorker.controller`가 `null`이 아니고, 등록의 `scope`가 `<origin>/`이다
- **검증** e2e `pwa.spec.ts`

### 정상 동작 — 캐시

> **이 절의 리터럴은 `frontend/src/test/fixtures.ts`의 값이다.** `hoffmann`은 id `2`,
> 제목 `James Hoffmann Ultimate V60`, 물 온도 `100°C`, 스텝 **7개**다. `kasuya`는 id `3`이고
> **상세 픽스처가 아직 없어 이번에 실제 백엔드 응답을 떠서 만든다**(스텝 6개).

#### AC-PWA-09 · 연 레시피가 캐시에 들어간다

- **Given** Service Worker가 등록됐고 `kaldi-recipe-v1`이 비어 있다
- **When** `/recipes/2`를 열어 화면이 그려진다
- **Then** `kaldi-recipe-v1`의 키가 **1개**이고 그 URL이 `/api/v1/recipes/2`로 끝난다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-10 · 온라인에서는 캐시가 최신을 가리지 않는다

- **Given** `/recipes/2`를 한 번 열어 물 온도 `100°C`가 캐시에 들어갔다
- **When** 스텁의 `waterTempC`를 `94`로 바꾼 뒤 `/recipes/2`를 다시 연다
- **Then** 화면에 `94°C`가 있고 `100°C`는 없다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-11 · 오프라인에서 연 적 있는 레시피가 열린다

- **Given** 온라인에서 `/recipes/2`를 한 번 열었다
- **When** 오프라인으로 바꾸고 `/recipes/2`를 새로고침한다
- **Then** 제목 `James Hoffmann Ultimate V60`과 푸어 스텝 **7개**가 화면에 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-12 · 오프라인에서 연 적 없는 레시피는 안내로 떨어진다

- **Given** 온라인에서 `/recipes/2`만 열었다
- **When** 오프라인으로 바꾸고 `/recipes/3`을 연다
- **Then** `연결 없음`이 화면에 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-13 · 오프라인 콜드 스타트가 로그인으로 튕기지 않는다

- **Given** 온라인에서 `/recipes/2`를 한 번 열었다
- **When** 오프라인으로 바꾸고 `/recipes/2`를 새로고침한 뒤 5초 기다린다
- **Then** 경로가 `/recipes/2` 그대로이고 `/login`으로 시작하지 않는다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-14 · 인증 만료는 지금처럼 로그인으로 보낸다

- **Given** 온라인이고 `/api/auth/refresh`가 HTTP `401`을 돌려준다
- **When** `/recipes/2`를 연다
- **Then** 경로가 `/login?next=%2Frecipes%2F2`가 된다
- **검증** 단위 `useRequireSession.test.tsx`

#### AC-PWA-15 · 로그아웃하면 레시피 캐시가 빈다

- **Given** `/recipes/2`를 열어 `kaldi-recipe-v1`에 항목이 1개 있다
- **When** `/more`에서 `로그아웃`을 누른다
- **Then** `kaldi-recipe-v1`의 키가 **0개**다
- **검증** e2e `pwa.spec.ts`

### 정상 동작 — 오프라인 화면

#### AC-PWA-16 · 저장된 레시피가 목록으로 나온다

- **Given** 온라인에서 `/recipes/2`와 `/recipes/3`을 열었다
- **When** 오프라인으로 바꾸고 `/offline`을 연다
- **Then** `James Hoffmann Ultimate V60`과 `Tetsu Kasuya 4:6 Method`가 모두 화면에 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-17 · 목록의 항목이 실제로 열린다

- **Given** 오프라인이고 `/offline`에 `Tetsu Kasuya 4:6 Method`가 있다
- **When** 그 항목을 누른다
- **Then** 경로가 `/recipes/3`이 되고 푸어 스텝 **6개**가 화면에 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-18 · 캐시가 비면 그렇게 말한다

- **Given** `kaldi-recipe-v1`이 비어 있다
- **When** 오프라인으로 바꾸고 `/offline`을 연다
- **Then** `저장된 레시피가 없습니다`가 화면에 있다
- **검증** e2e `pwa.spec.ts`

### 경계값

> 이 둘만 **합성 스텁**을 쓴다 — id `101`부터 `151`까지가 각각 자기 id를 담은 응답을 낸다.
> 개수만 세고 내용은 보지 않으므로 지어낸 픽스처가 가정을 검증하는 문제가 생기지 않는다.
> 서로 다른 레시피 51개를 실제 응답으로 뜨는 것은 불가능하다.

#### AC-PWA-19 · 50개까지는 전부 남는다

- **Given** `kaldi-recipe-v1`이 비어 있다
- **When** `/recipes/101`부터 `/recipes/150`까지 **50개**를 차례로 연다
- **Then** `kaldi-recipe-v1`의 키가 **50개**이고, `/api/v1/recipes/101`로 끝나는 키가 그중에 있다
- **검증** e2e `pwa.spec.ts`

#### AC-PWA-20 · 51번째에서 가장 오래된 것이 빠진다

- **Given** `/recipes/101`부터 `/recipes/150`까지 50개를 열었다
- **When** `/recipes/151`을 연다
- **Then** `kaldi-recipe-v1`의 키가 **50개**이고, `/api/v1/recipes/101`로 끝나는 키가 **없으며**, `/api/v1/recipes/151`로 끝나는 키가 있다
- **검증** e2e `pwa.spec.ts`

### 에러

#### AC-PWA-21 · 캐시에 없는 API 요청은 오프라인에서 503으로 끝난다

- **Given** 오프라인이고 `kaldi-recipe-v1`에 `/api/v1/recipes/3`이 없다
- **When** 페이지에서 그 URL로 `fetch`를 보낸다
- **Then** 응답 `status`가 `503`이고 본문이 `{"code":"OFFLINE","message":"네트워크에 연결되어 있지 않습니다."}`다
- **검증** e2e `pwa.spec.ts`

> 이 스펙의 유일한 에러 코드다. 서버가 내는 것이 아니라 **Service Worker가 만들어 내는 응답**이므로
> 백엔드의 `ErrorCode` enum에는 추가하지 않는다.

## 수동 확인

- [ ] 폰에서 「홈 화면에 추가」로 실제로 설치되고, 아이콘과 이름이 의도대로 보인다
- [ ] 설치한 앱을 열면 브라우저 주소창 없이 뜬다 (`display: standalone`이 실제로 먹는지)
- [ ] 비행기 모드로 바꾼 뒤 홈화면 아이콘으로 앱을 열어 저장된 레시피로 실제 커피를 내려본다
- [ ] 마스커블 아이콘이 안드로이드 런처의 원형·사각형 마스크에서 잘리지 않는다

## 열어둔 결정

- **앱 셸 캐시의 버전 올리기.** 지금은 `kaldi-shell-v1` 하나이고 배포해도 이름이 그대로다. Next의
  자산 경로가 해시라 낡은 파일이 남아도 참조되지 않지만, 쌓이기만 한다. **실제로 용량이 문제가 될 때**
  버전 접미사를 올리고 옛 캐시를 지우는 규칙을 정한다.
- **`/offline` 목록의 정렬.** 지금은 Cache Storage가 돌려주는 순서(넣은 순)를 그대로 쓴다. 「최근 연
  순」이 필요해지면 그때 넣은 시각을 함께 저장한다.
- **브루잉 로그 상세의 오프라인.** 로그는 스텝을 레시피에서 읽어오므로 레시피가 캐시에 있으면 절반은
  이미 있다. 기록을 보며 내리는 흐름(`2026-09-03-web-brew-log-steps`)이 폰에서 실제로 쓰이는지 확인한
  뒤 판단한다.
- **설치 유도 배너.** 브라우저 기본 경로로 설치가 실제로 일어나는지 본 뒤, 안 되면 그때 연다.
