# 웹 달력 그리드 반응형 재설계 스펙

> 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md) 참조.
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**
>
> `docs/specs/2026-09-19-home-calendar.md`의 후속이다. AC ID는 그 스펙의 번호를 이어(`85`부터)
> 쓴다 — 같은 컴포넌트(`Calendar.tsx`)를 다루는 같은 기능 영역이기 때문이다.

## 무엇을

**웹(`≥1100px`) 달력 그리드를 목업(`docs/archive/design/design_handoff_kaldi_note/Kaldi Note Home -
Calendar Web.dc.html`)에 맞춰 반응형으로 다시 만든다.** 지금은 그리드 전체 높이가 `420px`
고정이라 화면 크기와 무관하게 같은 비율로 눌려 있다 — `flex:1`로 남는 세로 공간을 채우게 바꾼다.
동시에 목업에 있는 그리드선·선택/오늘 숫자 표시를 추가한다.

### 범위 밖 (Non-goals)

- **우측 컬럼(`DayList`)의 카드 틀·태그 줄.** 목업은 카드(배경+테두리+모서리+패딩)에 원두·기구·
  시각 캡션과 비율·온도·시간·별점 태그 줄까지 있지만, 지금 구현은 밋밋한 목록 줄이다. 좌측
  그리드와 결이 다른 별개 기능 격차라 이번 범위에서 뺀다 — 별도 스펙으로 연다.
- **`760~1099px`(1컬럼) 그리드에 이 반응형 채움을 적용하는 것.** 1컬럼은 달력 아래에 날짜
  목록이 바로 붙으므로, 달력을 뷰포트 높이에 맞춰 늘리면 목록이 밀려난다. 지금처럼 내용 기반
  높이를 유지한다.
- **백엔드 변경.** 0건.

## 왜

목업과 나란히 보면 지금 화면이 눌려 있다는 게 눈에 보인다 — `420px` 고정 높이는 애초에 임의의
수였고, 화면이 커질수록 달력이 화면의 일부만 쓰고 나머지가 빈다. 그리드선이 없어서 셀 경계가
안 보이고, 선택된 날짜가 셀 배경만 바뀔 뿐 목업처럼 숫자 자체가 도장처럼 찍히지 않는다.

## 용어

| 용어 | 정의 |
|---|---|
| **행 높이** | 그리드 한 주(7일)가 차지하는 세로 픽셀. 달이 6주에 걸치면 5주보다 행이 하나 더 많아 행 하나의 높이가 줄어든다 |
| **채움** | 그리드 전체 높이를 고정값이 아니라 `flex:1`로 부모가 남긴 세로 공간만큼 갖는 것 |

## 어떻게 동작 — 인수 조건

### 정상 동작

#### AC-HOMECAL-85 · `≥1100px`에서 그리드가 남는 세로 공간을 채운다

- **Given** 뷰포트 폭 `1440px`, 높이 `900px`
- **When** 홈을 연다
- **Then** 달력 그리드(`role="grid"` 안의 주 컨테이너)의 렌더된 높이가 `420px`가 아니다 —
  뷰포트 높이에 따라 달라진다(예: 높이 `900px`일 때와 `1100px`일 때 그리드 높이가 다르다)
- **검증** e2e `home-calendar-web.spec.ts`

#### AC-HOMECAL-86 · 행 높이가 `64px` 밑으로 내려가야 하면 페이지가 스크롤된다

- **Given** 뷰포트 폭 `1440px`, 높이를 그리드 6행이 각 `64px`를 유지하기엔 부족한 값(예:
  `500px`)으로 줄인 상태
- **When** 홈을 연다
- **Then** 그리드의 각 행 높이가 `64px` 미만으로 줄지 않고, `document.documentElement`의
  `scrollHeight`가 `window.innerHeight`보다 크다(페이지가 세로로 스크롤된다)
- **검증** e2e `home-calendar-web.spec.ts`

#### AC-HOMECAL-87 · 그리드선 — 상단은 `divider-strong`, 내부는 `sunken`, 폭 `1px`

- **Given** 뷰포트 폭 `1440px`
- **When** 그리드의 상단 테두리와 셀 사이 내부 선의 색을 읽는다
- **Then** 상단 테두리는 `--divider-strong` 토큰 값, 내부 선은 `--sunken` 토큰 값이고 둘 다
  `1px`다
- **검증** e2e `home-calendar-web.spec.ts`

#### AC-HOMECAL-88 · 셀 안쪽 여백이 상하 `8px`·좌우 `12px`다

- **Given** 뷰포트 폭 `1440px`
- **When** 날짜가 있는 셀의 `getComputedStyle`을 읽는다
- **Then** `paddingTop`·`paddingBottom`이 `8px`, `paddingLeft`·`paddingRight`가 `12px`다
- **검증** e2e `home-calendar-web.spec.ts`

#### AC-HOMECAL-89 · 선택된 날짜 숫자가 `24px` 원으로 감전다

- **Given** 뷰포트 폭 `1440px`, `2026-09-05`가 선택된 상태
- **When** 그 셀의 날짜 숫자 요소를 본다
- **Then** 렌더된 크기가 `24px × 24px`인 원(`border-radius: 50%`)이고 배경색이 `--ink`,
  글자색이 `--on-ink` 토큰 값이다
- **검증** e2e `home-calendar-web.spec.ts`

#### AC-HOMECAL-90 · 오늘이지만 선택 안 된 날짜 숫자에 `1px` 링이 있다

- **Given** 뷰포트 폭 `1440px`, 오늘(`2026-09-19`)이 선택되지 않은 상태(다른 날짜가 선택됨)
- **When** 오늘 셀의 날짜 숫자 요소를 본다
- **Then** `border`가 `1px`이고 색이 `--border` 토큰 값이며, 배경은 채워지지 않는다(선택된
  날짜의 채운 원과 구분된다)
- **검증** e2e `home-calendar-web.spec.ts`

### 경계값

#### AC-HOMECAL-91 · `1099px`(1컬럼)에서는 이 반응형 채움을 쓰지 않는다

- **Given** 뷰포트 폭 `1099px`
- **When** 홈을 연다
- **Then** 그리드 높이가 뷰포트 높이 변화에 반응해 늘어나지 않는다 — 내용 기반(고정 또는
  콘텐츠 기준) 높이를 유지한다. `AC-HOMECAL-85`의 반대 경계를 확인한다
- **검증** e2e `home-calendar-web.spec.ts`
