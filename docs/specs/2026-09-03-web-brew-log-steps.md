# 브루잉 로그 상세에서 레시피의 푸어 스텝을 본다 스펙

> 2026-09-03 `/interview`로 확정. 작성 규칙은 [`docs/conventions/workflow.md`](../conventions/workflow.md).
> **모든 인수 조건은 자동화된 테스트로 옮길 수 있어야 한다.**

## 무엇을

브루잉 로그 상세(`/brews/{id}`)에 **그 로그가 가리키는 레시피의 푸어 스텝**을 실측값 바로 아래에 보여준다. **읽기 전용이다.**

백엔드는 바꾸지 않는다. 이 화면은 레시피 이름을 얻으려고 이미 `GET /recipes/{recipeId}`를 부르고 있고, **그 응답에 `steps`가 통째로 들어 있다** — 새 요청이 늘지 않는다.

### 범위 밖 (Non-goals)

- **★ 로그에서 푸어 스텝을 수정하는 것.** 푸어링을 바꾸는 것은 **새 레시피를 만드는 일**이지 기록을 고치는 일이 아니다. 바꾸고 싶으면 레시피를 포크한다(`docs/specs/2026-08-18-recipe-fork.md`). 백엔드도 이미 그렇게 돼 있다 — `BrewLogPatchRequest`에 스텝도 `recipeId`도 없고, 편집 화면 스펙(`docs/specs/2026-09-02-web-brew-log-edit.md`)의 「레시피와 원두는 바꿀 수 없다」가 화면 쪽을 막고 있다. **이 절은 읽기 전용이고 편집 진입점을 두지 않는다.**
- **저장 후 이동 변경.** 지금처럼 `/brews/{id}`로 간다. 스텝이 붙어 상세가 충분해지면 「잘못 이동한 것 같다」는 느낌이 사라질 것으로 본다 — 아래 「수동 확인」에서 되묻는다.
- **로그에 스텝 스냅샷을 저장하는 것**(`brew_log_steps`). 아키텍처 문서가 「타이머 도입 시 자동 채움」으로 자리만 잡아둔 것이고, 이번에 만들지 않는다.
- **편집 화면(`/brews/{id}/edit`)의 스텝 표시.** 거기는 실측값을 고치는 곳이다.
- **목록 카드의 스텝.** 카드는 훑는 용도다.

## 왜

**친구가 써보고 말한 것이다.** 로그를 보고 "아, 이 레시피로 다시 내려야겠다" 하고 상세에 들어갔는데 **수치만 있고 레시피 내용이 없다.** 몇 초에 몇 g을 붓는지가 이 서비스의 핵심인데 기록 화면에서 그것을 볼 수 없다.

지금 상세에 있는 것은 실측값(원두량·물량·온도·시간)과 추출 분석뿐이다. 그 숫자만으로는 커피를 내릴 수 없다.

레시피 상세로 가는 링크는 제목에 이미 있지만, **내리는 중에 화면을 오가는 것은 부엌에서 폰을 쓰는 상황과 맞지 않는다.** 젖은 손으로 뒤로 가기를 누르게 만들지 않는다.

## 용어

| 용어 | 정의 |
|---|---|
| 푸어 스텝 | 레시피의 `steps`. 몇 초에 어떤 방식으로 몇 g을 붓는지의 시퀀스 |
| 스텝 절 | 이번에 상세에 새로 넣는 영역. 제목은 `푸어 스텝` |
| 읽는다 | `GET /recipes/{recipeId}`가 200을 주는 것. 남의 `PRIVATE` 레시피는 403이라 읽지 못한다 |

## 화면

상세의 절 순서가 이렇게 된다. **`푸어 스텝`이 새로 들어가는 자리다.**

```
날짜 · 제목(레시피 링크) · 원두
실측값        원두량 20.0g · 물 300.0g · 온도 92°C · 시간 3:30
푸어 스텝     ← 새로 넣는 절
추출 분석
메모
편집 · 삭제
```

절 제목 `푸어 스텝`은 레시피 상세가 쓰는 문구와 같다. 같은 것을 두 화면에서 다르게 부르지 않는다.

표시는 `RecipeStepList`를 그대로 재사용한다 — 누적 물량 계산이나 스텝 라벨을 두 번 만들지 않는다.

## 못 읽을 때

**스텝 절을 통째로 그리지 않는다.** 제목 자리에 이미 `비공개 레시피`·`삭제된 레시피` 같은 문구가 떠 있어(`docs/specs/2026-09-02-web-entity-names.md`) 이유가 드러난다. 같은 말을 두 번 하지 않는다.

조회 중에도 그리지 않는다. 빈 절이 먼저 나타났다가 채워지면 화면이 흔들린다.

## 어떻게 동작 — 인수 조건

### 정상 동작

#### AC-WEBLOGSTEP-01 · 레시피를 읽었으면 스텝이 순서대로 보인다

- **Given** `/brews/42`를 연다. 로그의 `recipeId`가 `12`이고, `GET /recipes/12`가 `steps` 6개를 주며 그중 첫째가 `stepOrder: 1`·`stepType: "BLOOM"`·`waterG: 50.0`이다
- **When** 화면이 그려진다
- **Then** `푸어 스텝`이라는 제목이 화면에 있고, 목록 항목이 `6`개이며, 첫 항목에 `블룸`과 `50g`이 보인다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

#### AC-WEBLOGSTEP-02 · 스텝 절은 실측값 뒤, 추출 분석 앞에 온다

- **Given** `/brews/42`를 연다. 로그에 `tdsPercent`가 있어 추출 분석 절이 그려진다
- **When** 세 제목 `실측값`·`푸어 스텝`·`추출 분석`의 문서상 위치를 비교한다
- **Then** `실측값` → `푸어 스텝` → `추출 분석` 순이다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

#### AC-WEBLOGSTEP-06 · 스텝이 없는 레시피면 그 사실이 보인다

- **Given** `/brews/42`를 연다. `GET /recipes/12`가 `steps: []`를 준다
- **When** 화면이 그려진다
- **Then** `푸어 스텝` 제목이 있고 `등록된 스텝이 없습니다`가 보인다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

#### AC-WEBLOGSTEP-07 · 스텝 절은 읽기 전용이다

- **Given** `/brews/42`를 연다. `GET /recipes/12`가 `steps` 6개를 준다
- **When** `푸어 스텝` 제목이 속한 절 안을 확인한다
- **Then** 그 안에 `button`·`textbox`·`combobox` 역할을 가진 요소가 `0`개다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

> 푸어링을 바꾸는 것은 새 레시피를 만드는 일이다. 이 조건이 「여기서 바로 고치면 편하겠네」로 시작되는 회귀를 막는다.

### 못 읽을 때

#### AC-WEBLOGSTEP-03 · 권한이 없으면 스텝 절이 없다

- **Given** `/brews/42`를 연다. `GET /recipes/12`가 HTTP `403`, `code: "FORBIDDEN"`으로 실패한다
- **When** 화면이 그려진다
- **Then** `푸어 스텝`이라는 제목이 화면에 없다. `비공개 레시피`는 보인다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

#### AC-WEBLOGSTEP-04 · 삭제된 레시피면 스텝 절이 없다

- **Given** `/brews/42`를 연다. `GET /recipes/12`가 HTTP `404`, `code: "NOT_FOUND"`로 실패한다
- **When** 화면이 그려진다
- **Then** `푸어 스텝`이라는 제목이 화면에 없다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

#### AC-WEBLOGSTEP-05 · 조회 중에는 스텝 절이 없다

- **Given** `/brews/42`를 연다. `GET /recipes/12`의 응답이 아직 도착하지 않았고, 로그 응답은 도착했다
- **When** 그 시점의 화면을 확인한다
- **Then** `푸어 스텝`이라는 제목이 화면에 없다
- **검증** 화면 테스트 `src/app/brews/[id]/page.test.tsx`

## 수동 확인

- [ ] 폰에서 로그 상세를 열어 스텝을 보며 실제로 커피를 내려본다 — 스크롤 없이 다음 스텝이 보이는지, 젖은 손으로 넘길 만한지
- [ ] **저장 후 도착 화면이 여전히 어색한지 친구에게 다시 물어본다.** 이번 변경이 그 불편을 없앴는지가 「저장 후 이동을 바꾸지 않는다」는 결정의 근거였다

> **둘 다 남은 채로 `구현완료`로 올렸다**(2026-09-03, 사람 결정). `verification.md`의 「수동 확인이 남으면 올리지 않는다」와 어긋나지만, 남은 둘은 **폰 실물 조작 감각**과 **친구 되묻기**라 세션이 밟을 수 없고, 초안으로 두면 AC 7개의 자동 검사까지 함께 멈춘다. `2026-09-02-web-entity-names.md`도 같은 이유로 미체크인 채 `구현완료`다.
>
> 대신 **360×800 스텁 화면은 스크린샷으로 확인했다** — 절 순서(실측값 → 푸어 스텝 → 추출 분석), 제목 크기, `RecipeStepList`가 이 폭에서 넘치지 않는 것까지. 남은 것은 실물 감각뿐이다.

## 열어둔 결정

- **레시피가 기록 이후 수정됐을 때 알릴지.** 로그는 실측값을 스냅샷으로 갖지만 스텝은 갖지 않는다. 내린 뒤 레시피를 고치면 실측값과 스텝이 서로 어긋나 보인다. `recipe.updatedAt`과 `log.createdAt`으로 기계적 판정이 가능하나 이번엔 미룬다 — **실제로 헷갈리는 일이 생기면 그때 다룬다.**
- **스텝을 보며 내릴 때의 진행 표시.** 타이머나 현재 스텝 강조는 별도 기능이다. 추출 타이머를 다룰 때 함께 정한다.
