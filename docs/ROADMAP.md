## 왜 이 문서가 생겼나

2026-09-23 기준 계획이 두 갈래로 나뉘어 있었다.

| | 출처 | 상태 |
|---|---|---|
| 공식 로드맵 | `product-direction.md` 12단계 (2026-09-16) | 1·2단계 완료, 3단계 승인 후 미구현, **4~9단계 스펙 0개** |

계획이 하나로 정리되지 않은 상태에서 가장 눈에 띄는 것(목업과의 차이)부터 손대게 된 결과다.

**완료 정의:** 레시피를 검색·필터로 찾아 내 서랍에 「담고」, 내 잔 통계를 웹과 모바일에서 본다.

| 스펙 | 상태 |
|---|---|
| 검색·필터·통계·담기 API (`2026-09-21-recipes-and-brews-search-api.md`) | 승인 · 브랜치 `feat/recipes-and-brews-search-api` · 커밋 0 |
| 웹 둘러보기 / 내 서랍 (RW1·RW2) | 미작성 |

### M2 · 기록 흐름

**완료 정의:** 기록 작성 → 상세에서 레시피와 비교(차이를 문장으로) → 「다시 내리기」로 새 기록이 한 흐름으로 이어진다. 웹 기록 상세는 2컬럼이다.

- 기록 작성 화면 리디자인 (`/brews/new` + 원두 다이얼로그, `screens-v2/BrewNew`)
- 기록 상세 웹 2컬럼 (③, 디자인 W3 — 비교표 「차이」 열 별도)
- 비교표 자연어 문구 · 「다시 내리기」 (small-features에서 흡수)
- 흡수: ③, ⑤의 일부

### M3 · 추출 도구

**완료 정의:** 푸어 타이머로 레시피 스텝을 따라 내리고 결과가 기록으로 이어진다. 환산기에서 마이크론 → 내 그라인더 클릭수로 역환산하고, 결과로 바로 기록을 연다.

- 푸어 타이머 (⑨, `product-direction` 10단계, 디자인 M7)
- 분쇄도 환산기 재구성 (④) + 마이크론 → 클릭수 역환산 (12단계, 역환산 가능 그라인더 3개 제약 포함)
- 「이 값으로 기록하기」 (small-features에서 흡수)
- 내 기구 관리 — `user-grinders` 수정·삭제 API가 선행돼야 한다 (small-features 범위 밖이었던 것)

### M4 · 친구 피드

**완료 정의:** 맞팔로우 상대의 최근 잔을 피드로 보고, 그 잔의 레시피를 담는다.

- 친구 피드 (⑩, 11단계, 디자인은 Mockups v2에만 있음)

## 상시 트랙 — 시각 보정

**마일스톤이 아니다.** 목업과의 차이는 발견될 때마다 다음 규칙으로 처리한다.

- 한 번에 반나절 상한. 넘으면 다음 마일스톤 안으로 넣는다
- 새 스펙을 만들지 않는다 — 이슈 1개 + 목업 대비 스크린샷 비교로 검증 (작업 방식 개정은 별도 논의)

## 운영 규칙

- **동시에 진행하는 마일스톤은 1개.** 끝나기 전에 다음 마일스톤의 인터뷰를 시작하지 않는다
- 마일스톤이 끝나면 이 문서의 해당 항목을 「완료 (날짜, PR 번호)」로 바꾼다
- 순서를 바꾸거나 항목을 추가하려면 이 문서를 먼저 고친다. JOURNAL에 순서 목록을 따로 만들지 않는다
